1. Правила та їх рівні

Кожне правило можна вимкнути або задати йому рівень серйозності:

  • "off" або 0 — вимкнено;
  • "warn" або 1 — попередження (не валить збірку);
  • "error" або 2 — помилка (ненульовий код виходу).
rules: {
  'no-console': 'warn',
  'eqeqeq': 'error',              // вимагати === замість ==
  'no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
}

Деякі правила приймають додаткові опції — тоді значенням є масив [рівень, опції], як у no-unused-vars вище.

2. Вимкнення в коді

Іноді правило треба обійти точково — це роблять коментарями:

// eslint-disable-next-line no-console
console.log('лише тут дозволено');

/* eslint-disable no-alert */
alert('вимкнено для цілого блоку');
/* eslint-enable no-alert */

Вимикати правило — крайній захід. Якщо доводиться робити це часто, можливо, правило зайве (тоді вимкни його в конфізі глобально) або код справді варто переписати. Масові eslint-disable знецінюють лінтер.

3. Плагіни

Плагіни додають правила для конкретних технологій. Їх ставлять через npm і підключають у конфізі.

// приклад: правила для React-хуків
import reactHooks from 'eslint-plugin-react-hooks';

export default [
  {
    plugins: { 'react-hooks': reactHooks },
    rules: {
      'react-hooks/rules-of-hooks': 'error',
      'react-hooks/exhaustive-deps': 'warn',
    },
  },
];

Популярні: eslint-plugin-react, eslint-plugin-jsx-a11y, @typescript-eslint, eslint-plugin-import.

4. ESLint і TypeScript

Для TS є готовий набір typescript-eslint, що додає типозалежні правила:

import tseslint from 'typescript-eslint';

export default tseslint.config(
  ...tseslint.configs.recommended,
);

5. Різні правила для різних файлів

Завдяки масиву конфігів легко застосувати правила лише до частини файлів:

export default [
  { files: ['**/*.test.js'], rules: { 'no-console': 'off' } },
  { files: ['src/**/*.js'],  rules: { 'no-console': 'error' } },
];
