1. Вкладені роутери

Тримати всі процедури в одному роутері незручно. Роутери вкладаються: кожну предметну область (користувачі, пости, todo) описуємо окремим роутером, а тоді збираємо в кореневий appRouter. 

// server/routers/todo.ts
export const todoRouter = router({
  list: publicProcedure.query(() => db.todos.findMany()),
  add: publicProcedure
    .input(z.object({ title: z.string().min(1) }))
    .mutation(({ input }) => db.todos.create(input)),
});

// server/router.ts — кореневий роутер
export const appRouter = router({
  todo: todoRouter,
  user: userRouter,
});
export type AppRouter = typeof appRouter;

На клієнті шлях повторює структуру: trpc.todo.add.useMutation(), trpc.user.byId.useQuery(...). Вкладеність роутерів = простір імен процедур.

2. Контекст (context)

Контекст — це об'єкт, який tRPC створює на кожен запит і передає в усі процедури. Сюди кладуть те, що потрібно всім: підключення до БД, дані про поточного користувача (з cookie/токена), заголовки запиту. 

// server/context.ts
import type { CreateExpressContextOptions } from '@trpc/server/adapters/express';

export function createContext({ req, res }: CreateExpressContextOptions) {
  const user = getUserFromToken(req.headers.authorization); // може бути null
  return { db, user };
}

export type Context = typeof createContext extends (...a: any) => infer R ? R : never;

Контекст — це місце для автентифікації. Тут ми один раз розбираємо токен і кладемо user у контекст, а процедури лише читають ctx.user. У наступному уроці на цьому збудуємо «захищені процедури».

3. Прив'язка контексту до tRPC

Щоб ctx був типізований у процедурах, тип контексту передають у initTRPC ще на ініціалізації: 

// server/trpc.ts
import { initTRPC } from '@trpc/server';
import type { Context } from './context';

const t = initTRPC.context<Context>().create();

export const router = t.router;
export const publicProcedure = t.procedure;

Тепер у будь-якій процедурі ctx знає про db та user: 

me: publicProcedure.query(({ ctx }) => {
  return ctx.user; // тип виведено з Context
}),

4. Передати createContext адаптеру

Лишилось сказати адаптеру, як будувати контекст на кожен запит:

app.use('/trpc', createExpressMiddleware({
  router: appRouter,
  createContext, // ← викликається на кожен запит
}));

5. Підсумок

  • вкладені роутери групують процедури й задають простір імен;
  • контекст — спільні для запиту дані (БД, користувач), доступні як ctx;
  • тип контексту прив'язується через initTRPC.context<Context>().

Серверна частина готова. Далі — типізований клієнт і хуки TanStack Query.
