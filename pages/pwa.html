1. Що таке PWA

PWA (Progressive Web App) — це звичайний веб-застосунок, який завдяки кільком технологіям поводиться майже як «рідний» мобільний: його можна встановити на телефон/десктоп, він працює офлайн, має іконку й запускається у власному вікні без адресного рядка.

PWA стоїть на трьох китах:

  • HTTPS — безпечний контекст (обовʼязково);
  • Service Worker — офлайн і кешування (попередній урок);
  • Web App Manifest — метадані для встановлення (нижче).

2. Web App Manifest

manifest.json описує застосунок для системи: назву, іконки, кольори, режим відображення. Підключається лінком у <head>. 

// manifest.json
{
  "name": "Мій нотатник",
  "short_name": "Нотатки",
  "start_url": "/",
  "display": "standalone",          // власне вікно, без браузерного UI
  "background_color": "#ffffff",
  "theme_color": "#2563eb",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
<!-- index.html -->
<link rel="manifest" href="/manifest.json">
<meta name="theme-color" content="#2563eb">

3. Встановлення

Якщо є маніфест, SW і HTTPS, браузер сам пропонує «Встановити застосунок». Можна перехопити цю подію й показати власну кнопку: 

let deferred;
window.addEventListener('beforeinstallprompt', (e) => {
  e.preventDefault();
  deferred = e;            // зберегти подію
  showInstallButton();     // показати свою кнопку
});

installBtn.addEventListener('click', async () => {
  deferred.prompt();       // показати системний діалог встановлення
  await deferred.userChoice;
});

4. Найпростіший шлях: vite-plugin-pwa

Руками робити маніфест, іконки й SW — марудно. Плагін vite-plugin-pwa (на базі Workbox) генерує SW із precache-маніфестом і під’єднує все автоматично: 

// vite.config.js
import { VitePWA } from 'vite-plugin-pwa';

export default {
  plugins: [
    VitePWA({
      registerType: 'autoUpdate',
      manifest: {
        name: 'Мій нотатник',
        theme_color: '#2563eb',
        icons: [ /* ... */ ],
      },
    }),
  ],
};

У Next.js PWA роблять через плагіни (напр. next-pwa) або власний SW у public/. Принцип той самий: manifest + Service Worker + HTTPS.

5. Перевірка й аудит

Готовність PWA перевіряють у DevTools: вкладка Application (Manifest, Service Workers, Cache) та аудит Lighthouse (розділ PWA/Best Practices). Він підкаже, чого бракує до встановлюваного офлайн-застосунку.

6. Коли PWA доречна

  • ✅ контент/інструмент, яким користуються часто (пошта, нотатки, дашборд, читалка);
  • ✅ хочеш «встановлюваність» без магазинів застосунків;
  • ⚠️ потрібен глибокий доступ до заліза (Bluetooth, точні сенсори) — можливості PWA ширшають, але подекуди все ще поступаються нативним застосункам.
