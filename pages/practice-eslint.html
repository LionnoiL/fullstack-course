Практика: ESLint + Prettier

Візьми будь-який свій JS-проєкт (або порожню папку з npm init -y) і налаштуй у ньому повний конвеєр якості коду. Перевіряй кожен крок у терміналі.

Завдання 1. Підключити ESLint

Встанови ESLint, створи eslint.config.js з рекомендованим набором правил і додай скрипти lint та lint:fix у package.json.

Рішення 
npm install -D eslint @eslint/js
// eslint.config.js
import js from '@eslint/js';

export default [
  js.configs.recommended,
  { rules: { 'no-unused-vars': 'warn', eqeqeq: 'error' } },
];
"scripts": { "lint": "eslint .", "lint:fix": "eslint . --fix" }

Завдання 2. Спіймати й виправити помилки

Створи файл із навмисними проблемами (невикористана змінна, == замість ===). Запусти npm run lint, розберись у звіті, потім npm run lint:fix.

Підказка

Не все виправляється автоматично: ==→=== ESLint виправить, а невикористану змінну — ні (це може змінити логіку). Прибери її вручну.

Завдання 3. Додати Prettier без конфліктів

Встанови Prettier і eslint-config-prettier, створи .prettierrc, підключи конфіг останнім у ESLint. Переконайся, що після prettier --write ESLint не лається на стиль.

Рішення 
npm install -D prettier eslint-config-prettier
// eslint.config.js
import prettier from 'eslint-config-prettier';
export default [ /* ...правила... */ prettier ]; // останнім

Завдання 4. Автоматизація (виклик)

Налаштуй Husky + lint-staged так, щоб перед кожним комітом змінені файли автоматично проходили eslint --fix і prettier --write. Перевір: спробуй закомітити неохайний файл.

Налаштуй форматування при збереженні у своєму редакторі (editor.formatOnSave) і поклади .vscode/settings.json у репозиторій. Так конвеєр якості почне працювати непомітно — код чиститься сам, ще до коміту.
