1. Сервер розробки

Команда npm run dev піднімає локальний сервер із живим перезавантаженням. Vite віддає модулі на вимогу, тож старт майже миттєвий незалежно від розміру проєкту.

npm run dev

// VITE ready in 320 ms
// ➜  Local:   http://localhost:5173/
// ➜  Network: use --host to expose

2. HMR — гаряча заміна модулів

Hot Module Replacement оновлює в браузері лише той модуль, який ти змінив, без перезавантаження сторінки. Стан застосунку (введений текст, відкрита вкладка) при цьому зберігається.

Правиш CSS — стилі оновлюються миттєво й без миготіння. У фреймворках (React, Vue) HMR працює «з коробки» через офіційні плагіни.

HMR — головна причина, чому розробка на Vite відчувається такою швидкою: цикл «зберіг файл → побачив результат» скорочується до частки секунди, і не треба щоразу відновлювати стан сторінки вручну.

3. HMR API для власного коду

У чистому JS можна підписатися на оновлення модуля вручну через import.meta.hot:

if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    // застосувати оновлений модуль без перезавантаження
    console.log("модуль оновлено", newModule);
  });
}

4. Налаштування сервера

Порт, автовідкриття браузера й доступ по мережі задають у vite.config.js:

import { defineConfig } from 'vite';

export default defineConfig({
  server: {
    port: 3000,   // інший порт
    open: true,   // відкрити браузер автоматично
    host: true,   // доступ з інших пристроїв у мережі
  },
});

5. Проксі для API

Щоб під час розробки звертатися до бекенду без CORS-проблем, налаштуй проксі:

server: {
  proxy: {
    // запити на /api підуть на локальний бекенд
    '/api': 'http://localhost:8080',
  },
}
