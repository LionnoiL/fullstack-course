1. CSS і препроцесори

CSS у Vite просто імпортують у JS — стилі автоматично потраплять на сторінку:

// src/main.js
import './style.css';

Для SCSS достатньо поставити компілятор — Vite підхопить його сам, без додаткової конфігурації:

npm install -D sass
// далі просто: import './style.scss';

CSS-модулі працюють «з коробки» — файл *.module.css дає локальні імена класів:

import styles from './card.module.css';
element.className = styles.card; // клас без конфліктів імен

2. Зображення та статичні ресурси

Ассет, імпортований у JS, повертає готовий URL. Під час збірки Vite додасть до імені хеш (для кешування) і за потреби вбудує дрібні файли як base64.

import logoUrl from './logo.svg';
img.src = logoUrl;

3. Папка public

Файли з public/ віддаються «як є» за кореневим шляхом і не проходять обробку. Підходить для favicon.ico, robots.txt, файлів зі сталим ім'ям.

<!-- public/favicon.ico доступний як /favicon.ico -->
<link rel="icon" href="/favicon.ico" />

4. Змінні оточення

Vite читає файли .env. Щоб змінна потрапила в код клієнта, її ім'я має починатися з VITE_ — це захист від випадкового витоку секретів у бандл.

// .env
VITE_API_URL=https://api.example.com
DB_PASSWORD=secret   // без префікса VITE_ — у клієнт НЕ потрапить
// доступ у коді
const url = import.meta.env.VITE_API_URL;
console.log(import.meta.env.MODE); // 'development' | 'production'

Усе, що з префіксом VITE_, вбудовується у зібраний JS і видиме користувачу. Ніколи не клади туди паролі, приватні ключі чи токени — лише публічні значення (адреси API, ключі аналітики тощо).
