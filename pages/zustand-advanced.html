1. Асинхронні дії

Дія може бути async — усередині просто викликаєш set у потрібний момент. Ніякої додаткової обгортки не треба. 

export const useUsers = create((set) => ({
  users: [],
  loading: false,
  fetchUsers: async () => {
    set({ loading: true });
    const res = await fetch('/api/users');
    set({ users: await res.json(), loading: false });
  },
}));

Для даних із сервера краще підходить TanStack Query. Async-дії Zustand доречні для клієнтської логіки (напр. зберегти чернетку) або в невеликих застосунках, де окрема бібліотека запитів надлишкова.

2. Middleware persist

Обгортка persist зберігає стан у localStorage й відновлює його при перезавантаженні — стан «переживає» оновлення сторінки. 

import { create } from 'zustand';
import { persist } from 'zustand/middleware';

export const useCart = create(
  persist(
    (set) => ({
      items: [],
      add: (item) => set((s) => ({ items: [...s.items, item] })),
    }),
    { name: 'cart' } // ключ у localStorage
  )
);

3. Middleware devtools

Обгортка devtools під'єднує стор до Redux DevTools — видно кожну зміну стану. 

import { devtools } from 'zustand/middleware';

export const useStore = create(
  devtools((set) => ({ /* ... */ }))
);
// middleware можна комбінувати: devtools(persist(...))

4. Розбиття на «слайси»

Великий стор ділять на частини-функції й об'єднують — щоб файл не розростався:

const createUserSlice = (set) => ({
  user: null,
  setUser: (user) => set({ user }),
});
const createCartSlice = (set) => ({
  items: [],
  add: (i) => set((s) => ({ items: [...s.items, i] })),
});

export const useStore = create((...a) => ({
  ...createUserSlice(...a),
  ...createCartSlice(...a),
}));

5. Коли Zustand — правильний вибір

  • потрібен простий глобальний стан без церемоній;
  • не хочеться провайдерів і бойлерплейту;
  • команда невелика, а домовленості гнучкі.
