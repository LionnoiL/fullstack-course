1. Навіщо тестувати

Автоматичні тести перевіряють, що код працює правильно, і не дають зламати вже готове під час змін. Вони економлять час на ручній перевірці й додають впевненості при рефакторингу.

Основні види: модульні (окрема функція), інтеграційні (кілька частин разом), e2e (сценарій користувача цілком).

2. Модульні тести (Vitest)

Vitest (та схожий Jest) — популярні тест-раннери. Тест складається з describe, test/it та перевірок expect.

npm install -D vitest
// sum.js
export function sum(a, b) {
  return a + b;
}

// sum.test.js
import { describe, test, expect } from 'vitest';
import { sum } from './sum';

describe('sum', () => {
  test('додає два числа', () => {
    expect(sum(2, 3)).toBe(5);
  });

  test('працює з відʼємними', () => {
    expect(sum(-1, 1)).toBe(0);
  });
});

3. Поширені перевірки (matchers)

expect(value).toBe(5);              // строга рівність
expect(obj).toEqual({ a: 1 });      // глибока рівність
expect(arr).toContain('js');
expect(value).toBeTruthy();
expect(fn).toThrow();
expect(value).toBeGreaterThan(3);

4. Тестування React (Testing Library)

React Testing Library перевіряє компоненти так, як їх бачить користувач.

import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import Counter from './Counter';

test('лічильник збільшується', async () => {
  render(<Counter />);
  const button = screen.getByRole('button');

  await userEvent.click(button);

  expect(screen.getByText('1')).toBeInTheDocument();
});

Тестуйте поведінку, а не деталі реалізації: «при кліку зʼявляється результат», а не «викликано таку функцію». Такі тести переживають рефакторинг.

5. Запуск

npx vitest          # стежити за змінами
npx vitest run      # разово (для CI)
