1. Web-first перевірки

Перевірки Playwright — «web-first»: expect(locator) сам повторює перевірку, доки вона не пройде або не спливе таймаут. Це прибирає цілий клас flaky-тестів, де елемент ще не встиг оновитися. 

import { test, expect } from '@playwright/test';

// чекає, поки елемент стане видимим (не падає одразу)
await expect(page.getByRole('heading', { name: 'Дякуємо!' })).toBeVisible();

Різниця важлива: expect(await locator.isVisible()) перевіряє миттєвий стан і легко падає. await expect(locator).toBeVisible() — чекає. Майже завжди потрібен другий варіант.

2. Поширені перевірки

await expect(locator).toBeVisible();
await expect(locator).toBeHidden();
await expect(locator).toHaveText('Готово');        // точний текст
await expect(locator).toContainText('успішно');    // частковий
await expect(locator).toHaveValue('ann@mail.com'); // значення поля
await expect(locator).toBeEnabled();
await expect(locator).toBeChecked();
await expect(locator).toHaveCount(3);              // скільки елементів
await expect(page).toHaveURL(/\/dashboard/);       // адреса
await expect(page).toHaveTitle(/Профіль/);

3. Таймаути й негативні перевірки

// індивідуальний таймаут для повільної дії
await expect(page.getByText('Звіт готовий')).toBeVisible({ timeout: 15000 });

// заперечення
await expect(page.getByText('Помилка')).not.toBeVisible();

4. Скриншоти й візуальні перевірки

Playwright уміє порівнювати скриншоти з еталоном — зручно ловити візуальні регресії:

await expect(page).toHaveScreenshot('home.png'); // перший раз створює еталон
await expect(page.getByRole('article')).toHaveScreenshot('card.png');

Візуальні тести чутливі до шрифтів і ОС — тому їх зазвичай ганяють у сталому середовищі (Docker/CI). При навмисній зміні дизайну еталон оновлюють: --update-snapshots.

5. Трейси й діагностика падінь

Коли тест падає, найцінніше — trace: покроковий запис із DOM-знімками, мережею й консоллю на кожній дії. Вмикається в конфігу (trace: 'on-first-retry'). 

npx playwright show-trace trace.zip   # відкрити trace viewer

А також автоматичні скриншот і відео при падінні — налаштовуються в use:

use: {
  screenshot: 'only-on-failure',
  video: 'retain-on-failure',
  trace: 'on-first-retry',
}

Перевірки освоєно — час скласти з дій і перевірок реальні сценарії.
