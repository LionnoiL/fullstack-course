1. Область видимості

Область видимості (scope) — це незалежна від мови концепція, яка описує доступність змінних у виконуваному коді.

Scope chain (ланцюжок областей видимості) - області видимості утворюють ієрархію, так що дочірні області мають доступ до змінних з батьківських областей, але не навпаки.

Змінну видно для виконуваного коду, якщо вона є в поточній області видимості або в ланцюжку областей видимості функції.

Є три типи областей видимості:

  • Змінні, оголошені на самому верхньому рівні, тобто поза будь-яких конструкцій на зразок if, while, for і функцій, знаходяться в глобальній області видимості.
  • Змінні, оголошені всередині інструкцій if, циклів і інших блоків коду знаходяться в блочній області видимості.
  • Змінні, оголошені всередині функцій, знаходяться в області видимості функції.

Це можна уявити, як будинок з кімнатами. Будинок знаходиться в глобальному контексті. Кожна функція і блок створюють нову кімнату, вкладену всередину будинку. Змінні, оголошені всередині цих кімнат, доступні тільки тоді, коли ви знаходитесь усередині цієї кімнати. Поза кімнати ці змінні недоступні.

// Global scope

function foo() {
  // Local function scope of foo

  if (true) {
    // Local block scope
  }

  // Local function scope of foo

  function bar() {
    // Local function scope of bar
  }

  // Local function scope of foo
}

// Global scope

Інтерпретатор намагається спочатку знайти змінну в тій області видимості, в якій до неї звернулися. Якщо такої змінної в локальній області видимості немає, то він виходить назовні, на один рівень за спробу, поки не знайде значення або не дійде до самої верхньої області видимості (глобальної) і зрозуміє, що змінну з таким ідентифікатором неможливо знайти, оскільки її просто немає, тоді буде помилка про те, що змінна не оголошена.

Функція add повертає суму a і b. Змінна a оголошена усередині функції, b ні.

const b = 10;

const add = function() {
  const a = 5;

  return a + b;
};

add(); // 15

Намагаючись вирішити вираз a + b, інтерпретатор шукає значення a і b. Пошук починається всередині локальної області видимості - всередині функції add. Він знаходить значення a і переходить до b. Неможливо знайти значення b в локальній області видимості, тому пошук розширюється до зовнішньої області. Тут він знаходить b — це 10. Вираз a + b перетворюється в 5 + 10, в результаті отримуємо 15.

2. Область видимості функції

Як вже говорилося, функції створюють власну локальну область видимості. Змінні, створені всередині функції, включаючи параметри, локальні всередині цієї функції і не доступні коду із зовні. Локальні змінні будуть створюватися кожен раз при виконанні функції, і їх окремі інкарнації ніяк один з одним не пов'язані.

Глобальний value оголошений поза тілом функції і його значення буде виведено в консоль. Локальний value всередині функції add як і раніше видно тільки всередині цієї функції. Ці два value не мають нічого спільного один з одним, вони знаходяться в різних областях видимості. Вони не об'єднуються в одне ціле, не дивлячись на те, що у них одне і те ж ім'я. Своєю чергою innerValue недоступна поза тілом функції.

const value = 50;

const add = function(num) {
  const value = 10;
  const innerValue = 5;

  return num + value + innerValue;
};

// value оголошений глобально і тому доступний
console.log(value); // 50

console.log(add(20)); // 35

// Помилка, змінна innerValue не оголошена в цій області
// видимості, вона доступна тільки всередині функції add
console.log(innerValue);

Така поведінка допомагає запобігти випадковій взаємодії між функціями. Якби всі змінні використовувалися в будь-якому місці програми, було б дуже важко переконатися, що одна змінна не використовується для різних операцій.

Ставлячись до локальних для функцій змінних так, що вони існують тільки всередині функції, мова робить можливим роботу з функціями ніби з ізольованими контейнерами, що дозволяє не хвилюватися про весь код повністю.

3. Hoisting

У мовах програмування, в тому числі в JavaScript, код виконується у дві фази.

Фаза компіляції, інтерпретації або оцінки (compile time, evaluation time) - підготовка перед виконанням коду, перевірка валідності синтаксису вихідного коду.

Під час цієї фази компілятор або інтерпретатор знаходить синтаксичні помилки, помилки типізації та т. д. Тобто код ще не виконується, тільки оцінюється. Якщо ця фаза пройшла успішно, це як мінімум означає що в коді немає синтаксичних помилок і його можна запустити на виконання.

Фаза виконання (runtime) - скрипт починає виконуватися, виконуються інструкції викликів функцій і оцінки виразів, відбувається пошук необхідних ідентифікаторів у відповідних областях видимості тощо.

Якщо ця фаза завершилася успішно, значить скрипт написаний без явних помилок і закінчив свою роботу. На цій фазі можуть бути помилки пов'язані з відсутніми властивостями і змінними, перетворенням типів і т. д., тобто щось, що відбувається тільки під час виконання коду.

Спробуйте виконати наступний код. Оскільки ми зробили помилку і замість const намагаємося оголосити змінну value ключовим словом cos, на фазі компіляції буде виявлена ​​синтаксична помилка і фаза виконання навіть не запуститься. В консолі ми відразу побачимо повідомлення про помилку.

console.log('Цього повідомлення не буде в консолі.');

cos value = 5;

Підняття змінних (hoisting) - це механізм інтерпретатора, який, до фази виконання коду, підіймає оголошення змінних в початок області видимості (блочної або функції) в якій вони були оголошені.

Саме тому працює function declaration і так дивно поводяться змінні оголошені використовуючи var - їх оголошення підіймаються в початок області видимості функції в якій вони були оголошені.

// Ось тому ми використовуємо let або const

console.log(value); // undefined
value = 5;

if (true) {
  console.log(value); // 5
  var value = 10;
  console.log(value); // 10
}

value = 15;
console.log(value); // 15

Змінні оголошені використовуючи let або const так само підіймаються, але при цьому підкоряються блочні області видимості, нічим не ініціалізуются за замовчуванням і не доступні для звернення до того місця в коді де були оголошені в коді.

// У кожній області видимості буде створена своя, незалежна змінна value

console.log(value); // ReferenceError: value is not defined
const value = 5;
console.log(value); // 5

if (true) {
  console.log(value); // ReferenceError: value is not defined
  const value = 10;
  console.log(value); // 10
}

console.log(value); // 5

Більш детально про підняття ідентифікаторів і ключові слова var, let і const читайте в цій статті.
