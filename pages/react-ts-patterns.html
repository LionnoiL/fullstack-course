1. Узагальнені (generic) компоненти

Компонент-список може працювати з будь-яким типом елемента. Дженерик робить його типобезпечним для кожного випадку.

type ListProps<T> = {
  items: T[];
  render: (item: T) => React.ReactNode;
};

function List<T>({ items, render }: ListProps<T>) {
  return <ul>{items.map((it, i) => <li key={i}>{render(it)}</li>)}</ul>;
}

// T виведеться як User — render отримає саме User
<List items={users} render={(u) => u.name} />;

2. Об'єднання пропсів (дискриміновані)

Коли набір пропсів залежить від «режиму», описують об'єднання — TS не дасть змішати несумісні варіанти.

type Props =
  | { as: 'link'; href: string }
  | { as: 'button'; onClick: () => void };

function Action(props: Props) {
  if (props.as === 'link') return <a href={props.href}>Лінк</a>;
  return <button onClick={props.onClick}>Кнопка</button>;
}

3. Utility-типи на службі

Типи з розділу TypeScript особливо корисні в React:

type User = { id: number; name: string; email: string };

// форма редагування без id
type EditProps = Omit<User, 'id'>;

// усі поля необов'язкові (частковий апдейт)
function update(patch: Partial<User>) { /* ... */ }

// дістати тип пропсів чужого компонента
type BtnProps = React.ComponentProps<typeof MyButton>;

Omit, Partial, Pick дозволяють виводити типи пропсів з уже наявних, а не дублювати їх. Одне джерело правди для типу User — і всі похідні оновляться автоматично.

4. Типи для даних із API

Описуй форму відповіді сервера окремим типом і приводь дані одразу після fetch — далі весь компонент працює з відомою структурою.

type Todo = { id: number; title: string; done: boolean };

async function loadTodos(): Promise<Todo[]> {
  const res = await fetch('/api/todos');
  return res.json() as Promise<Todo[]>;
}

5. Тип, що повертає компонент

Явно анотувати повернення компонента зазвичай не треба — TS виведе його сам. Уникай застарілого React.FC: він додає неочевидні нюанси, а звичайна функція з типізованими пропсами читабельніша.
