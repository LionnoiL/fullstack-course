1. Контекст виконання (this)

Можна з упевненістю сказати, що ключове слово this є однією з найбільш заплутаних частин JavaScript на старті вивчення. Новачки часто підставляють This методом наукового тику до тих пір поки скрипт не спрацює 😐.

Контекст в JavaScript схожий на контекст в реченні:

  • Петя біжить швидко, тому що Петя намагається зловити поїзд.
  • Петя біжить швидко, тому що він намагається зловити поїзд.

Друга пропозиція звучить лаконічніше. Предметом пропозиції є Петя, і ми можемо сказати, що контекст пропозиції - це Петя, тому що він в центрі уваги в це конкретний час в реченні. Навіть займенник хто відноситься до Петі.

І точно так же об'єкт може бути поточним контекстом виконання функції.

// Петя біжить швидко, тому що Петя намагається зловити поїзд.
const petya = {
  name: 'Petya',
  showName() {
    console.log(petya.name);
  },
};

petya.showName();

Звернення до властивостей об'єкта всередині методів, використовуючи ім'я самого об'єкта, аналогічно використанню Петя замість він.

У всіх функцій є локальна змінна this. Під час виконання функції, в змінну this записується посилання на об'єкт, в контексті якого вона викликається.

This нам потрібен для доступу до методів і властивостей об'єкта, який викликає функцію, тим більше, що найчастіше ім'я викликає об'єкта не відомо.

// Петя біжить швидко, тому що він (this) намагається зловити поїзд.
const petya = {
  name: 'Petya',
  showName() {
    console.log(this.name);
  },
};

petya.showName();

2. Правила визначення this

Необхідно засвоїти лише одне правило для визначення this.

Значення контексту всередині функції визначаться не в момент її створення, а в момент виклику. Тобто значення this визначається тим, як викликається функція, а не де вона була оголошена.

2.1. this в глобальному контексті

У глобальному контексті, якщо скрипт виконується не в строгому режимі, This посилається на об'єкт window. У строгому режимі, значення this, в глобальному контексті, буде undefined.

function fn() {
  console.log(this);
}

fn(); // window без "use strict" і udefined с "use strict"

2.2. this в методі об'єкту

Якщо функція була викликана як метод об'єкта, то контекст буде посилатися на об'єкт, частиною якого є метод.

const petya = {
  name: 'Petya',
  showThis() {
    console.log(this);
  },
  showName() {
    console.log(this.name);
  },
};

petya.showThis(); // {name: "Petya", showThis: ƒ, showName: ƒ}
petya.showName(); // 'Petya'

Більш складний приклад для кращого розуміння:

  • Спочатку створимо функцію в глобальному контексті, і викличемо її.
  • Після чого дамо її в властивість об'єкта і викличемо як метод цього об'єкта.
function showThis() {
  console.log('this in showThis: ', this);
}

// Викликаємо в глобальному контексті
showThis();
// this in showThis: Window

const user = { name: 'Mango' };

/*
 * Записуємо посилання на функцію в властивість об'єкта
 * Зверніть увагу, що це не виклик - немає ()
 */
user.showContext = showThis;

/*
 * Викликаємо функцію в контексті об'єкта
 * This буде вказувати на поточний об'єкт, в контексті
 * Якого здійснюється виклик, а не на глобальний об'єкт.
 */

user.showContext();
// this in showThis: {name: "Mango", showContext: ƒ}

2.3. this у функціях зворотного виклику

Коли ми передаємо метод, який використовує this, як параметр, який буде використовуватися як функція зворотного виклику, буде проблема. Розв'язання цієї проблеми розглядається в наступній секції.

const hotel = {
  name: 'Resort Hotel',
  showThis() {
    console.log(this);
  },
};

const fn = function (callback) {
  /*
   * Під час виклику fn, callback буде посиланням
   * На функцію showThis об'єкта hotel.
   * Її виклик відбувається в глобальному контексті,
   * Про hotel вона нічого не знає.
   * Відповідно this НЕ буде посилатися на hotel
   */
  callback();
};

// Передається посилання на функцію, а не її виклик
fn(hotel.showThis); // window або undefined

2.4. this в стрілкових функціях

Стрілкові функції не мають свого this. На відміну від звичайних функцій, змінити значення this всередині стрілки після її оголошення не можна.

Контекст всередині стрілки визначається місцем її оголошення, а не виклику, і посилається на контекст батьківської функції.

Стрілкові функції також ігнорують наявність суворого режиму. якщо стрілка запам'ятала глобальний контекст, то this в ній буде містити посилання на Window незалежно чи виконується скрипт в строгому режимі чи ні.

const showThis = () => {
  console.log('this in showThis: ', this);
};

showThis(); // this in showThis: window

const user = { name: 'Mango' };
user.showContext = showThis;

user.showContext(); // this in showThis: window

Обмежуючи Стрілкові функції постійним контекстом, JavaScript-движки можуть краще їх оптимізувати, на відміну від звичайних функцій, значення this яких може бути змінено.

Приклад не практичний, але відмінно показує як працює контекст для стрілок. Значення контексту береться з батьківської області видимості.

const hotel = {
  name: 'Resort hotel',
  showThis() {
    const fn = () => {
      /*
       * Стрілки запам'ятовують контекст під час оголошення,
       * З батьківської області видимості
       */
      console.log('this in fn: ', this);
    };

    fn();
    console.log('this in showThis: ', this);
  },
};

hotel.showThis();
// this in fn: {name: 'Resort hotel', showThis: ƒ}
// this in showThis: {name: 'Resort hotel',showThis: ƒ}

Якщо привести цей код до ES5, вийде наступне.

const hotel = {
  name: 'Resort hotel',
  showThis: function showThis() {
    /*
     * Контекст для стрілки зберігається
     * І передається з зовнішньої області видимості
     */
    const context = this;

    const fn = function fn() {
      // А тут використовується
      console.log('this in fn: ', context);
    };

    fn();
    console.log('this in showThis: ', this);
  },
};

hotel.showThis();
// this in fn: {name: 'Resort hotel', showThis: ƒ}
// this in showThis: {name: 'Resort hotel',showThis: ƒ}

3. Методи функцій call, apply, bind

Присвоєння функції в якості методу об'єкта може здатися гарною ідеєю, але чи варто зберігати подібні методи? Дублювання вже існуючих функцій у вигляді методів об'єкта буде займати ресурси, не приносячи жодних помітних вигод.

Тепер уявіть що у вас 150 готелів і для кожного необхідно виконати ту ж саму операцію при кожному привітанні гостя. Нам як мінімум хочеться відразу винести цей загальний код в функцію.

Функція це насправді досить хитрий об'єкт, тому у неї теж є методи. За допомогою методів call і apply можна виконати функцію в контексті якогось об'єкта, не роблячи функцію його методом.

const greet = function () {
  return `Wellcome to ${this.name} hotel!`;
};

const hotel = { name: 'Resort Hotel' };

console.log(greet.call(hotel)); // "Wellcome to Resort Hotel!"
console.log(greet.apply(hotel)); // "Wellcome to Resort Hotel!"

3.1. call і аргументи

fn.call(obj, arg1, arg2, ...)

Запам'ятати правило використання call досить легко: метод call викличе функцію fn передавши її this посилання на об'єкт obj, а також аргументиarg1, Arg2 і т. Д.

const greet = function (guest, stars) {
  return `${guest}, welcome to ${stars}-star ${this.name}!`;
};

const hotel = { name: 'Resort Hotel' };
const motel = { name: 'Sunlight Motel' };

console.log(greet.call(hotel, 'Mango', 5));
// "Mango, wellcome to 5-star Resort Hotel!"

console.log(greet.call(motel, 'Poly', 4));
// "Poly, wellcome to 4-star Sunlight Motel!"

3.2. apply і аргументи

fn.apply(obj, [arg1, arg2, ...])

Метод apply повний аналог методу call за винятком того, що синтаксис виклику аргументів вимагає неперерахування, а масив.

const greet = function (guest, stars) {
  return `${guest}, welcome to ${stars}-star ${this.name}!`;
};

const hotel = { name: 'Resort Hotel' };
const motel = { name: 'Sunlight Motel' };

console.log(greet.apply(hotel, ['Mango', 5]));
// "Mango, wellcome to 5-star Resort Hotel!"

console.log(greet.apply(motel, ['Poly', 4]));
// "Poly, wellcome to 4-star Sunlight Motel!"

3.3. bind

Ми розглянули випадки, коли необхідно миттєво викликати функцію з іншим контекстом, для цього використовуються методи call і apply. Але в разі функції зворотного виклику, коли необхідно не викликати функцію на місці, а передати посилання на цю функцію, причому з прив'язаним контекстом, call і apply НЕ підходять. Метод bind дозволяє розв'язати цю задачу.

`Bash const boundFn = fn.bind (obj, arg1, arg2, ...) `

Метод bind створює копію функції fn з прив'язаним контекстом obj і аргументами arg1,arg2 і так дале, після чого повертає її як результат своєї роботи. В результаті ми отримуємо копію функції з прив'язаним контекстом, яку можна передати куди завгодно і викликати коли завгодно.

const greet = function (guest) {
  return `${guest}, welcome to ${this.name}!`;
};

const hotel = { name: 'Resort Hotel' };

const hotelGreeter = greet.bind(hotel, 'Mango');

hotelGreeter(); // "Mango, wellcome to Resort Hotel!"

Найчастіше метод bind використовується для прив'язки контексту при передачі методів об'єкта як функцій зворотного виклику. Візьмемо проблемний приклад з попередньої секції. Завдання прив'язки контекста ми тепер можемо вирішити використовуючи метод bind, передавши функцією зворотного виклику копію методу з прив'язаним контекстом.

const hotel = {
  name: 'Resort Hotel',
  showThis() {
    console.log(this);
  },
};

const fn = function (callback) {
  callback();
};

// Передаємо копію методу showThis з контекстом прив'язаним до hotel
fn(hotel.showThis.bind(hotel)); // {name: "Resort Hotel", showThis: ƒ}
