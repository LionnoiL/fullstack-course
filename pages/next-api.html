1. Бекенд у тому ж проєкті

Next.js — фулстек-фреймворк: у ньому можна писати не лише сторінки, а й API-ендпоінти. Для цього створюють файл route.js у теці app/api/....

// app/api/hello/route.js  →  /api/hello
export function GET() {
  return Response.json({ message: 'Привіт із API' });
}

2. HTTP-методи

Кожен метод — це окрема експортована функція.

// app/api/users/route.js
export async function GET() {
  const users = await db.user.findMany();
  return Response.json(users);
}

export async function POST(request) {
  const body = await request.json();
  const user = await db.user.create({ data: body });
  return Response.json(user, { status: 201 });
}

3. Параметри та запити

// app/api/users/[id]/route.js
export async function GET(request, { params }) {
  const user = await db.user.findUnique({
    where: { id: Number(params.id) },
  });
  if (!user) {
    return Response.json({ error: 'Не знайдено' }, { status: 404 });
  }
  return Response.json(user);
}

Route Handlers використовують стандартні вебобʼєкти Request і Response — ті самі, що й fetch. Знання Fetch API з попередніх розділів переноситься сюди напряму.

4. Route Handler чи Server Action?

  • Server Action — для мутацій із власних форм застосунку;
  • Route Handler — коли потрібен публічний API (для мобільних клієнтів, вебхуків, сторонніх сервісів).
