1. Сценарій із формою

Складемо дії й перевірки в цілісний шлях користувача — реєстрацію:

test('реєстрація нового користувача', async ({ page }) => {
  await page.goto('/register');

  await page.getByLabel('Імʼя').fill('Аня');
  await page.getByLabel('Email').fill('ann@mail.com');
  await page.getByLabel('Пароль').fill('super-secret-1');
  await page.getByLabel('Приймаю умови').check();
  await page.getByRole('button', { name: 'Зареєструватися' }).click();

  // після успіху — редірект і привітання
  await expect(page).toHaveURL(/\/dashboard/);
  await expect(page.getByText('Привіт, Аня')).toBeVisible();
});

2. beforeEach і спільна підготовка

Повторювані кроки (відкрити сторінку, залогінитись) виносять у beforeEach: 

test.beforeEach(async ({ page }) => {
  await page.goto('/');
});

test.describe('кошик', () => {
  test('додавання товару', async ({ page }) => { /* ... */ });
  test('видалення товару', async ({ page }) => { /* ... */ });
});

3. Автентифікація без повторного входу

Логінитися в кожному тесті — повільно. Playwright дозволяє один раз увійти, зберегти стан сесії (cookie/localStorage) і перевикористати його: 

// auth.setup.ts — виконати один раз
import { test as setup } from '@playwright/test';

setup('авторизація', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill('ann@mail.com');
  await page.getByLabel('Пароль').fill('super-secret-1');
  await page.getByRole('button', { name: 'Увійти' }).click();
  await page.waitForURL('/dashboard');
  // зберегти сесію у файл
  await page.context().storageState({ path: 'playwright/.auth/user.json' });
});
// playwright.config.ts — підхопити збережений стан
use: { storageState: 'playwright/.auth/user.json' }

Це різко пришвидшує набір тестів: сесія зберігається один раз, і всі тести стартують уже залогіненими. Той самий підхід — для різних ролей (admin, звичайний користувач) через окремі файли стану.

4. Мокання мережі

Щоб тест був стабільним і швидким, зовнішні запити часто підміняють фіктивною відповіддю через page.route — не залежиш від реального API: 

test('показ товарів зі стабільними даними', async ({ page }) => {
  await page.route('**/api/products', async (route) => {
    await route.fulfill({
      json: [{ id: 1, title: 'Молоко' }, { id: 2, title: 'Хліб' }],
    });
  });

  await page.goto('/shop');
  await expect(page.getByText('Молоко')).toBeVisible();
});

Для компонентних та інтеграційних тестів (Vitest + Testing Library) ту саму роль грає MSW (Mock Service Worker) — перехоплює fetch на рівні мережі. У E2E зручніший вбудований page.route. Обидва дають детерміновані дані.

5. Page Object — порядок у великому наборі

Коли тестів багато, локатори й дії однієї сторінки виносять у клас — Page Object. Тести стають читабельними, а зміни в UI правляться в одному місці. 

class LoginPage {
  constructor(page) { this.page = page; }
  async login(email, pass) {
    await this.page.getByLabel('Email').fill(email);
    await this.page.getByLabel('Пароль').fill(pass);
    await this.page.getByRole('button', { name: 'Увійти' }).click();
  }
}
