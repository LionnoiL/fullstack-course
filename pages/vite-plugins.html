1. Файл vite.config.js

Уся конфігурація живе в vite.config.js у корені проєкту. Функція defineConfig дає підказки типів у редакторі. 

import { defineConfig } from 'vite';

export default defineConfig({
  root: '.',          // корінь проєкту
  base: '/',          // базовий публічний шлях
  plugins: [],        // список плагінів
  server: { port: 3000 },
  build: { outDir: 'dist' },
});

2. Плагіни

Плагіни розширюють Vite: підтримка фреймворків, PWA, стиснення тощо. Їх ставлять через npm і додають у масив plugins. 

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
});

Кілька популярних:

  • @vitejs/plugin-react / @vitejs/plugin-vue — підтримка фреймворків;
  • @tailwindcss/vite — інтеграція Tailwind CSS (див. розділ Tailwind);
  • vite-plugin-pwa — перетворення застосунку на PWA.

3. Аліаси шляхів

Щоб замість ../../../utils писати @/utils, налаштуй аліас:

import { defineConfig } from 'vite';
import { fileURLToPath, URL } from 'node:url';

export default defineConfig({
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
});
// тепер у будь-якому файлі:
import { formatDate } from '@/utils/date.js';

4. Різна конфігурація за режимом

Конфіг може бути функцією, що враховує режим (dev/build):

export default defineConfig(({ mode }) => ({
  build: {
    sourcemap: mode === 'development',
  },
}));

Vite сумісний із плагінами Rollup — тож екосистема плагінів дуже широка. Але починай із мінімального конфіга: у більшості проєктів достатньо одного плагіна фреймворка, а решта — за реальної потреби.
