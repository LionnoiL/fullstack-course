1. Сучасні оператори доступу

У реальних даних (особливо з сервера) частина полів може бути відсутня. Спроба звернутися до властивості undefined або null викидає помилку. Сучасний JavaScript (ES2020) дає два оператори, які роблять такий код коротшим і безпечнішим: опціональний ланцюжок ?. та нульове злиття ??.

2. Опціональний ланцюжок ?.

Оператор ?. зупиняє обчислення і повертає undefined, якщо ліва частина дорівнює null або undefined — замість того, щоб кинути помилку.

const user = { name: 'Ada' };

// Старий спосіб — багатослівна перевірка
const city1 = user.address && user.address.city;

// Опціональний ланцюжок
const city2 = user.address?.city; // undefined, без помилки

Працює також для методів і елементів масиву:

user.getName?.();       // викличе метод, лише якщо він існує
user.friends?.[0];      // безпечний доступ до елемента
data?.items?.length;    // ланцюжок будь-якої глибини

Не зловживайте ?.. Якщо значення завжди має існувати, краще нехай код впаде з помилкою — так ви раніше помітите баг, ніж отримаєте прихований undefined, що «протече» далі по програмі.

3. Нульове злиття ??

Оператор ?? повертає праву частину, лише якщо ліва — null або undefined. На відміну від ||, він не спрацьовує на «хибних, але валідних» значеннях: 0, '', false.

const count = 0;

count || 10;  // 10  — бо 0 хибний (часто небажано!)
count ?? 10;  // 0   — 0 є валідним значенням

const name = '' ?? 'Гість';   // '' — порожній рядок валідний
const nick = null ?? 'Гість'; // 'Гість'

4. Разом: значення за замовчуванням

Найпоширеніший приклад — дістати вкладене поле і підставити дефолт:

function getTheme(settings) {
  // якщо settings або theme відсутні — беремо 'light'
  return settings?.appearance?.theme ?? 'light';
}

getTheme({ appearance: { theme: 'dark' } }); // 'dark'
getTheme({});                                // 'light'
getTheme(undefined);                         // 'light'

Комбінувати ?? з || або && без дужок заборонено синтаксично — це змушує явно вказати пріоритет: (a ?? b) || c.
