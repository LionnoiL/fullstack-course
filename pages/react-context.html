1. Проблема «props drilling»

Коли дані потрібно передати глибоко вкладеному компоненту, доводиться «протягувати» пропси через усі проміжні рівні, які їх навіть не використовують. Це називають props drilling. Context API розвʼязує проблему: дані стають доступні будь-якому нащадку без передавання через кожен рівень.

2. Створення контексту

import { createContext } from 'react';

// значення за замовчуванням
export const ThemeContext = createContext('light');

3. Provider — надання значення

Компонент-провайдер огортає піддерево і задає значення контексту.

import { useState } from 'react';
import { ThemeContext } from './ThemeContext';

function App() {
  const [theme, setTheme] = useState('dark');

  return (
    <ThemeContext.Provider value={theme}>
      <Toolbar />
      <button onClick={() => setTheme('light')}>Світла тема</button>
    </ThemeContext.Provider>
  );
}

4. useContext — читання значення

Будь-який нащадок читає контекст хуком useContext — без пропсів.

import { useContext } from 'react';
import { ThemeContext } from './ThemeContext';

function Toolbar() {
  const theme = useContext(ThemeContext);
  return <div className={`toolbar ${theme}`}>Панель</div>;
}

5. Контекст зі станом

Часто в контекст кладуть і значення, і функції його зміни — так виходить простий глобальний стан. 

const AuthContext = createContext(null);

function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const value = { user, login: setUser, logout: () => setUser(null) };

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

Контекст добре підходить для «глобальних» даних, що рідко змінюються (тема, мова, поточний користувач). Для складного стану з частими оновленнями краще спеціалізовані рішення (Redux, Zustand) — надто «широкий» контекст спричиняє зайві рендери.
