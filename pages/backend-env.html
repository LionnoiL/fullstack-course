1. Змінні оточення

Секрети (паролі БД, ключі API, JWT-секрет) і налаштування, що відрізняються між середовищами, не можна зашивати в код. Їх виносять у змінні оточення. 

# файл .env (НЕ потрапляє в git)
PORT=3000
DATABASE_URL=postgresql://user:pass@localhost:5432/mydb
JWT_SECRET=super-secret-key

2. Пакет dotenv

npm install dotenv
require('dotenv').config();

const port = process.env.PORT || 3000;
const dbUrl = process.env.DATABASE_URL;

app.listen(port);

Обовʼязково додайте .env у .gitignore. Витік секретів у публічний репозиторій — одна з найпоширеніших і найнебезпечніших помилок.

3. .gitignore

# .gitignore
node_modules/
.env
dist/

4. Типова структура проєкту

project/
├─ src/
│  ├─ routes/      // маршрути
│  ├─ controllers/ // логіка обробників
│  ├─ middleware/  // проміжне ПЗ
│  └─ index.js     // точка входу
├─ prisma/
│  └─ schema.prisma
├─ .env
├─ .gitignore
└─ package.json

5. Різні середовища

Зазвичай є щонайменше development (локально) і production (на сервері). Значення беруть з оточення, а не з коду. 

const isProd = process.env.NODE_ENV === 'production';
if (!isProd) {
  app.use(require('morgan')('dev')); // логи лише в розробці
}
