1. Усі підходи поряд

Ми маємо кілька способів стилізувати компонентний застосунок. У кожного — своя ніша. Немає «єдино правильного»; є доречний під контекст. Порівняймо за чотирма ознаками: де живе стиль, рантайм (чи є JS-вартість у браузері), динаміка за пропсами й сумісність із Server Components (RSC).

  • Глобальний CSS / SCSS — стиль у .css/.scss; без рантайму; динаміка лише через перемикання класів; RSC — ✅.
  • CSS Modules — стиль у .module.css; без рантайму; динаміка через класи + clsx; RSC — ✅.
  • Tailwind — стиль у розмітці (утиліти); без рантайму; динаміка через умовні класи; RSC — ✅.
  • CSS-in-JS (runtime) — стиль у JS-компоненті; є рантайм; динаміка за пропсами повна; RSC — ⚠️ лише в клієнтських компонентах.
  • Zero-runtime (vanilla-extract, Panda) — стиль у .css.ts/JS; без рантайму (компілюється на збірці); варіанти задаються заздалегідь; RSC — ✅.

2. Як вибрати

  • Маленький сайт / лендинг → звичайний CSS/SCSS або Tailwind. Не ускладнюй.
  • Компонентний застосунок (Vite/CRA) → CSS Modules: простий, швидкий, без рантайму, звичайний CSS.
  • Багато динаміки, теми, дизайн-система в JS → CSS-in-JS (Emotion/ styled-components) — якщо перформанс не критичний і код клієнтський.
  • Next.js App Router / серверний рендер → CSS Modules або zero-runtime (vanilla-extract, Panda) — щоб не тягти рантайм у RSC.
  • Строгі типи й токени → zero-runtime.

Тренд 2024–2026: у Next.js-екосистемі runtime CSS-in-JS відступає на користь CSS Modules і zero-runtime через Server Components. У SPA (Vite) — усі підходи життєздатні; найбезпечніший дефолт — CSS Modules.

3. Чи можна змішувати

Так — і часто змішують: глобальний CSS для reset/змінних теми, CSS Modules для компонентів, Tailwind-утиліти для дрібних правок. Головне — узгодженість у команді: домовтесь про основний підхід, а не тягніть три одночасно «бо можна».

4. Продуктивність коротко

  • zero-runtime (CSS Modules, Tailwind, vanilla-extract) — стилі готові на збірці, у браузер іде чистий CSS: найшвидше;
  • runtime CSS-in-JS — додатковий JS + обчислення стилів під час рендеру; на великих списках відчутно;
  • для більшості застосунків різниця несуттєва — обирай за зручністю команди, а оптимізуй, коли є реальна проблема.

5. Підсумок розділу

  • проблема глобального CSS — конфлікти імен; рішення — локальний scope;
  • CSS Modules — звичайний CSS + унікальні класи на збірці, дефолт для більшості;
  • CSS-in-JS — стилі в JS із динамікою за пропсами; рантайм має ціну й обмеження в RSC;
  • zero-runtime — зручність CSS-in-JS без рантайму;
  • вибір — за контекстом (SPA vs Next, динаміка, типи, команда).
