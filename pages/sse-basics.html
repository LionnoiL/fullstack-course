1. Що таке SSE

Server-Sent Events — стандартний спосіб тримати одне HTTP-з'єднання відкритим і стрімити через нього події від сервера до клієнта. Це звичайний GET-запит із особливим типом відповіді text/event-stream, який не закривається. Однобічно: сервер → клієнт.

Плюси SSE: працює поверх звичайного HTTP (проходить через проксі/файрволи), автоматично перепідключається і памʼятає останній id події. Мінус: лише в один бік і (у старих браузерів) ліміт з'єднань на домен.

2. Клієнт: EventSource

У браузері є вбудований EventSource — жодних бібліотек:

const es = new EventSource('/api/stream');

es.onmessage = (event) => {
  const data = JSON.parse(event.data); // подія без імені
  console.log('нове:', data);
};

es.onerror = () => {
  // з'єднання впало — браузер сам спробує перепідключитись
};

3. Сервер (Express)

Сервер виставляє потрібні заголовки й пише події у відповідь, не закриваючи її. Формат кадру — рядки data: ...\n\n (порожній рядок завершує подію). 

app.get('/api/stream', (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');
  res.flushHeaders();

  const timer = setInterval(() => {
    res.write(`data: ${JSON.stringify({ time: Date.now() })}\n\n`);
  }, 1000);

  req.on('close', () => clearInterval(timer)); // клієнт відключився — прибрати
});

4. Іменовані події та id

Можна надсилати різні типи подій полем event: і нумерувати їх id: (браузер поверне останній id у заголовку Last-Event-ID після перепідключення): 

// сервер
res.write(`event: message\n`);
res.write(`id: 42\n`);
res.write(`data: ${JSON.stringify(msg)}\n\n`);

// клієнт — окремий обробник на іменовану подію
es.addEventListener('message', (e) => render(JSON.parse(e.data)));

Через retry: 5000\n\n сервер може задати інтервал перепідключення в мс.

5. Коли SSE — правильний вибір

  • стрічка сповіщень, live-лічильники, прогрес довгої задачі;
  • оновлення дашборда, ціни, статуси;
  • стрімінг відповіді LLM по токенах — теж часто SSE.

Якщо клієнту треба надсилати дані назад часто й миттєво (чат, курсори) — SSE не підійде, бо він однобічний. Тоді бери WebSocket з наступного уроку. Надіслати щось зрідка можна й окремим fetch-запитом поряд зі SSE.
