1. Отримання даних на сервері

У серверних компонентах дані отримують просто через async/await — без useEffect і станів завантаження. Код виконується на сервері, тож можна звертатися напряму до API чи бази.

export default async function Page() {
  const res = await fetch('https://api.example.com/posts');
  const posts = await res.json();

  return (
    <ul>
      {posts.map((p) => <li key={p.id}>{p.title}</li>)}
    </ul>
  );
}

2. Стратегії рендерингу

Next.js керує тим, коли генерується HTML, через опції кешування fetch:

  • SSG (статична генерація) — HTML будується під час збірки;
  • SSR — HTML будується на кожен запит;
  • ISR — статика, що періодично оновлюється.
// SSG — кешується назавжди (за замовчуванням)
fetch(url, { cache: 'force-cache' });

// SSR — свіжі дані на кожен запит
fetch(url, { cache: 'no-store' });

// ISR — оновлювати не частіше ніж раз на 60 секунд
fetch(url, { next: { revalidate: 60 } });

Next.js розширює стандартний fetch кешуванням і дедуплікацією: два однакові запити на одній сторінці виконаються лише раз.

4. Server Actions (мутації)

Для зміни даних (форми, створення записів) використовують Server Actions — серверні функції, що викликаються прямо з форми.

export default function Page() {
  async function createPost(formData) {
    'use server';
    await db.post.create({ data: { title: formData.get('title') } });
  }

  return (
    <form action={createPost}>
      <input name="title" />
      <button>Створити</button>
    </form>
  );
}
