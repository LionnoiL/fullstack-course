1. Проблема специфічності

У великих проєктах стилі починають «воювати»: щоб перекрити чуже правило, доводиться нарощувати специфічність або тулити !important. Каскадні шари (@layer) дають керувати пріоритетом стилів явно.

2. Оголошення шарів

Спершу оголошують порядок шарів — він визначає пріоритет. Пізніший шар перемагає, незалежно від специфічності селекторів усередині.

/* порядок: reset найслабший, utilities найсильніший */
@layer reset, base, components, utilities;

@layer base {
  a { color: blue; }
}

@layer components {
  .link { color: green; } /* переможе a, бо шар пізніший */
}

Ключова ідея: між шарами порядок важливіший за специфічність. Правило з пізнішого шару перекриє правило з ранішого, навіть якщо в раннього селектор «важчий». Це рятує від гонки специфічності й !important.

3. Незашаровані стилі — найсильніші

Стилі поза будь-яким шаром мають вищий пріоритет за будь-який шар. Тому власні override-и часто лишають поза шарами.

@layer components {
  .btn { color: gray; }
}

/* поза шаром — перекриє .btn із шару components */
.btn { color: black; }

4. Імпорт бібліотек у шар

Зручно завантажити чужий CSS у окремий шар — тоді свої стилі легко його перекривають без боротьби зі специфічністю:

@import url("bootstrap.css") layer(vendor);

@layer vendor, app; /* app сильніший за vendor */

5. Коли застосовувати

  • велика кодова база з багатьма авторами;
  • інтеграція сторонніх стилів, які треба перекривати;
  • дизайн-система з чіткими рівнями: reset → base → компоненти → утиліти.
