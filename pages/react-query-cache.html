1. Як працює кеш

Кожен запит зберігається в кеші під своїм queryKey. Якщо інший компонент запитає ті самі дані, TanStack Query віддасть їх із кешу миттєво, а за потреби тихо оновить у фоні. Однакові одночасні запити дедуплікуються в один.

2. staleTime — коли дані «застарівають»

staleTime визначає, скільки дані вважаються свіжими. Свіжі дані НЕ перезапитуються; щойно вони стають stale — бібліотека може оновити їх у фоні (при монтуванні, фокусі вікна тощо). 

useQuery({
  queryKey: ['todos'],
  queryFn: fetchTodos,
  staleTime: 5 * 60 * 1000, // свіжі 5 хвилин — без зайвих запитів
});

За замовчуванням staleTime: 0 — дані застарівають одразу, тому бачиш багато фонових оновлень. Це не помилка, а стратегія «завжди свіже». Для рідкозмінних даних підніми staleTime, щоб зменшити трафік.

3. gcTime — коли кеш очищається

gcTime (garbage collection, раніше cacheTime) — скільки невикористані дані лежать у кеші, перш ніж їх видалять. За замовчуванням 5 хвилин.

4. Інвалідація

Явно позначити дані застарілими й перезавантажити — invalidateQueries. Ключ можна вказати частково: інвалідуються всі запити, чий ключ починається з нього. 

// оновити конкретний список
queryClient.invalidateQueries({ queryKey: ['todos'] });

// оновити ВСЕ, що починається з ['todo'] — і ['todo'], і ['todo', 5]
queryClient.invalidateQueries({ queryKey: ['todo'] });

5. Пряме читання й запис кешу

// прочитати з кешу поза компонентом
const todos = queryClient.getQueryData(['todos']);

// записати вручну (напр. одразу після мутації, без запиту)
queryClient.setQueryData(['todos'], (old) => [...old, newTodo]);

6. Ручне оновлення

useQuery повертає refetch — виклик перезапитує дані на вимогу (напр. кнопка «Оновити»). 

const { data, refetch, isFetching } = useQuery({ /* ... */ });
<button onClick={() => refetch()} disabled={isFetching}>Оновити</button>
