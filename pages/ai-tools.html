1. Навіщо інструменти

Модель сама по собі не має доступу до твоєї БД, погоди чи актуальних цін — і не вміє надійно рахувати. Tool calling (function calling) розвʼязує це: ти описуєш функції, які модель може попросити викликати, вона повертає назву й аргументи, а виконуєш її ти — своїм кодом. Результат повертаєш моделі, і вона формулює відповідь.

Важливо: модель не виконує код — вона лише каже «виклич getWeather з {city: "Kyiv"}». Виконання, права й безпека — на твоєму боці. Це основа «агентів»: цикл «модель просить інструмент → ти виконуєш → модель продовжує».

2. Опис інструмента

Інструмент — це назва, опис (модель за ним вирішує, коли викликати) і JSON-схема входу:

const tools = [
  {
    name: 'get_weather',
    description: 'Отримати поточну погоду в місті. Викликай, коли питають про погоду.',
    input_schema: {
      type: 'object',
      properties: {
        city: { type: 'string', description: 'Назва міста' },
      },
      required: ['city'],
    },
  },
];

Пиши чіткий опис — коли саме викликати інструмент, а не лише що він робить. Від якості опису й схеми напряму залежить, чи модель викличе інструмент правильно.

3. Запит і відповідь із tool_use

Передаємо tools у запит. Якщо модель хоче інструмент, stop_reason буде 'tool_use', а в content буде блок tool_use з name та input:

const messages = [{ role: 'user', content: 'Яка погода в Києві?' }];

const res = await client.messages.create({
  model: 'claude-opus-4-8',
  max_tokens: 1024,
  tools,
  messages,
});

// res.stop_reason === 'tool_use'
const toolUse = res.content.find((b) => b.type === 'tool_use');
// toolUse.name === 'get_weather', toolUse.input === { city: 'Київ' }

4. Виконати й повернути tool_result

Виконуємо функцію своїм кодом і повертаємо результат моделі — обовʼязково з тим самим tool_use_id. Не забудь спершу додати відповідь моделі в історію:

const result = await getWeather(toolUse.input.city); // твоя функція

messages.push({ role: 'assistant', content: res.content }); // echo моделі
messages.push({
  role: 'user',
  content: [
    { type: 'tool_result', tool_use_id: toolUse.id, content: result },
  ],
});

// другий виклик — модель формулює фінальну відповідь із даними
const final = await client.messages.create({
  model: 'claude-opus-4-8',
  max_tokens: 1024,
  tools,
  messages,
});

5. Агентний цикл

Модель може попросити кілька інструментів поспіль. Тому обгортаємо все в цикл: доки stop_reason === 'tool_use' — виконуємо інструменти й продовжуємо; коли 'end_turn' — готово.

while (true) {
  const res = await client.messages.create({ model: 'claude-opus-4-8', max_tokens: 1024, tools, messages });
  messages.push({ role: 'assistant', content: res.content });

  if (res.stop_reason !== 'tool_use') break; // фінальна відповідь

  const results = [];
  for (const block of res.content) {
    if (block.type !== 'tool_use') continue;
    const output = await runTool(block.name, block.input); // диспетчеризація за назвою
    results.push({ type: 'tool_result', tool_use_id: block.id, content: output });
  }
  messages.push({ role: 'user', content: results });
}

Інструменти з побічними ефектами (запис у БД, надсилання листа, оплата) — перевіряй і за потреби підтверджуй перед виконанням. Модель може попросити будь-що; довіряй перевіреним аргументам і своїй авторизації, а не самому проханню.
