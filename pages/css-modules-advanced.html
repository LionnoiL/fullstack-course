1. composes — успадкування класів

Щоб не дублювати стилі, один клас може увібрати інший через composes (аналог «наслідування» для класів). Це чистіше, ніж чіпляти два класи в JSX. 

/* Button.module.css */
.base {
  padding: 0.6rem 1.2rem;
  border-radius: 6px;
  cursor: pointer;
}
.primary {
  composes: base;         /* увібрати стилі .base */
  background: #2563eb;
  color: #fff;
}
.danger {
  composes: base;
  background: #dc2626;
  color: #fff;
}
<button className={styles.primary}>OK</button>   // уже містить .base

composes можна брати й з іншого файлу: composes: base from './shared.module.css';. Так виносять спільні «примітиви» (кнопка, картка) в один модуль.

2. :global — навмисно глобальні стилі

Іноді клас треба не локалізовувати — напр. стилі сторонньої бібліотеки чи глобальні хелпери. Обгорни його в :global: 

:global(.swiper-slide) {   /* клас чужої бібліотеки — лишити як є */
  padding: 1rem;
}
.wrapper :global(.legacy) { color: #555; }  /* локальний .wrapper + глобальний .legacy */

3. Динамічні класи (clsx / classnames)

Часто клас залежить від стану (активний, помилка). Склеювати рядки вручну незручно — беруть крихітну бібліотеку clsx (або classnames): 

import clsx from 'clsx';
import styles from './Tab.module.css';

function Tab({ active, disabled }) {
  return (
    <button
      className={clsx(styles.tab, {
        [styles.active]: active,     // додасться, якщо active === true
        [styles.disabled]: disabled,
      })}
    />
  );
}

4. Тема через CSS-змінні

CSS Modules чудово поєднуються з CSS custom properties для тем: змінні оголошуєш глобально, а модулі їх використовують. Перемикання теми — зміна змінних, без перезбірки. 

/* globals.css */
:root { --accent: #2563eb; }
[data-theme='dark'] { --accent: #60a5fa; }

/* Button.module.css */
.primary { background: var(--accent); }

5. Типізація в TypeScript

За замовчуванням TS не знає, які ключі є в styles. Рішення: плагін або згенеровані .d.ts-типи (напр. typescript-plugin-css-modules), щоб styles. давав автодоповнення й ловив помилки в назвах класів.

Типізовані модулі перетворюють помилку в назві класу з «мовчазно нема стилю» на помилку компіляції — зручно в командних проєктах. Для старту достатньо й без типів.
