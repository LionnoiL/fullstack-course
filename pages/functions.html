1. Поняття функції

Дуже часто при створенні програм ділянка коду повторюється. А якщо програма велика, то виникає необхідність повторно використовувати подібні ділянки коду, часто з новими початковими значеннями. Втіленням цієї ідеї є функції.

Функція - це підпрограма, незалежна частина коду, призначена для виконання конкретного завдання.

Функції можна уявити як чорний ящик, вони отримують щось на вході (дані), і віддають щось на виході (результат виконання коду всередині функції).

Функції - це інструмент для структурування великих програм, зменшення повторень та ізолювання коду.

2. Функціональний вираз

Функціональний вираз (function expression) — звичайне оголошення змінної, значення якої буде функція.

Оголосимо змінну add, і дамо їй функцію, що приймає 3 значення і повертає результат складання цих значень.

Ім'я функції це дія, дієслово починається з маленької літери, що відповідає на питання 'Що зробити?'. Наприклад: findSmallesNumber, fetchUserInfo, validateInput. 

const add = function(a, b, c) {
  return a + b + c;
};

Визначення функції починається з ключового слова function, за яким може слідувати необов'язкове ім'я функції. В круглих дужках йдуть параметри — перерахування даних, які функція буде отримувати ззовні. Параметрів може бути кілька, або взагалі їх не бути, тоді записуються просто порожні круглі дужки ().

Далі йде тіло функції, укладену в фігурні дужки {}, що містить інструкції які необхідно виконати при виконанні функції. Тіло функції завжди укладають в фігурні дужки, навіть якщо воно складається з однієї інструкції.

Оператор return визначає значення, що повертається. Коли інтерпретатор доходить до return, він відразу ж виходить з функції, і повертає це значення в те місце коду, де функція була викликана.

Оператор return без вираження повертає значення undefined. При відсутності return в тілі функції, вона все одно поверне значення undefined.

Потім, коли необхідно, функція викликається за допомогою імені та круглих дужок, всередині яких можуть бути передані аргументи.

  • Термін аргументи використовується при виконанні функції, коли ми передаємо значення в функцію.
  • Термін параметри використовується при оголошенні функції, це ті локальні змінні всередині функції, в які будуть записані значення аргументів у час її виклику.

В JavaScript важливий порядок оголошення параметрів функції. Не існує ніякого іншого механізму пояснити інтерпретатору як значення аргументів функції при виклику пов'язані з параметрами.

Порядок оголошення параметрів відповідає порядку передачі аргументів при виклику функції: значення першого аргументу буде присвоєно першому параметру, другого аргументу другому параметру і т. д. Якщо параметрів буде менше ніж аргументів, то параметрами без значень буде присвоєно undefined.

// a, b, c це параметри
const add = function(a, b, c) {
  return a + b + c;
};

// 1, 2, 3 це аргументи
const result = add(1, 2, 3);
console.log(result); // 6

// 5, 10, 15 це аргументи
console.log(add(5, 10, 15)); // 30

Функція може або викликати побічні ефекти (змінювати загальні змінні), або повертати результат своєї роботи, залежить від завдання. Залежно від того, який фрагмент коду буде поміщений всередині функції, відбудеться або повернення обчисленого значення, або зміна стану програми, іноді обидва.

3. Порядок виконання коду

Якщо при виконанні коду, інтерпретатор зустрічає виклик функції, він призупиняє виконання поточного коду і починає виконувати код з тіла функції. Після того як весь код функції буде виконаний, інтерпретатор виходить з тіла функції, повертаючись в те місце, звідки прийшов, і продовжує виконувати код нижче виклику функції.

const fnA = function() {
  console.log('Почала виконуватися [fnA]');
  fnB();
  console.log('Продовжила виконуватися [fnA] після виходу з [fnB]');
};

const fnB = function() {
  console.log('Виконується [fnB]');
};

console.log('Почав виконання [main]');
fnA();
console.log('Продовжив виконуватися [main] після виходу з [fnA]');

/*
 * Почав виконання [main]
 * Почала виконуватися [fnA]
 * Виконується [fnB]
 * Продовжила виконуватися [fnA] після виходу з [fnB]
 * Продовжила виконуватися [main] після виходу з [fnA]
 */

Покроково розберемо виконання коду прикладу:

  • При вході в js-файл, код починає виконуватися зверху вниз.
  • Виклик fnA() змушує інтерпретатор призупинити виконання коду, і зайти в тіло функції fnA.
  • У функції fnA інтерпретатор зустрічає виклик функції fnB, яка перехоплює контроль і виконується.
  • Як тільки інтерпретатор виконав функцію fnB, тобто в ній стався return, в нашому випадку не явний, інтерпретатор повертається в функцію fnA і продовжує виконувати її з того місця де зупинився.
  • Як тільки інтерпретатор виконав функцію fnA, тобто в ній стався return, в нашому випадку не явний, інтерпретатор повертається в глобальний код і продовжує його виконання.

Виклич console.log(), через те, що це функція, теж перехоплюють контроль. Вони були пропущені для більш зрозумілого опису процесу.

4. Параметри за замовчуванням

При виконанні функції необов'язково вказувати значення всіх аргументів, які перераховані в параметрах функції. Але іноді, параметрам яким не передали значення через аргумент, буває необхідно присвоїти якесь значення, відмінне від undefined.

Нові можливості ES6 дозволяють зробити це дуже простим і очевидним чином, вказуючи значення за замовчуванням прямо при оголошенні параметрів в підпису функції. При такому записі, якщо значення переданого аргументу дорівнює undefined, в параметр записується значення за замовчуванням.

const count = function(countFrom = 0, countTo = 10, step = 1) {
  console.log(`countFrom = ${countFrom}, countTo = ${countTo}, step = ${step}`);

  for (let i = countFrom; i <= countTo; i += step) {
    console.log(i);
  }
};

count(1, 5); // countFrom = 1, countTo = 5, step = 1
count(2); // countFrom = 2, countTo = 10, step = 1
count(undefined, 5, 2); // countFrom = 0, countTo = 5, step = 2
count(); // countFrom = 0, countTo = 10, step = 1

5. Псевдо масив arguments

Доступ до набору всіх аргументів можна отримати через спеціальну локальну змінну arguments, яка доступна тільки всередині функції і зберігає всі аргументи як псевдо масив.

Псевдо масив — колекція, що має властивість length і можливість звернутися до елементу за індексом, але відсутністю більшості методів для роботи з масивом.

Псевдо масив arguments містить список аргументів, переданих функції при виклику, але кількість переданих аргументів може не збігатися з кількістю оголошених параметрів і це не призведе до помилки.

Розглянемо приклад використання arguments в функції, яка підсумовує будь-яку кількість аргументів:

const sum = function() {
  let total = 0;

  for (const argument of arguments) {
    total += argument;
  }

  return total;
};

console.log(sum(1, 2, 3)); //  6
console.log(sum(1, 2, 3, 4)); //  10
console.log(sum(1, 2, 3, 4, 5)); //  15

5.1. Способи перетворити псевдо масив

Оскільки у псевдо масива немає методів на кшталт slice() або includes(), часто необхідно перетворити його в повноцінний масив. На практиці використовують кілька основних способів перетворення.

Використовуючи метод Array.from(), який створить масив з ітеруючого об'єкта.

const fn = function() {
  // В змінній args буде повноцінний масив
  const args = Array.from(arguments);
};

Використовуючи операцію ... (rest), вона дозволяє зібрати будь-яку кількість елементів, в нашому випадку аргументів, в масив і зберегти його в змінну. Збираємо всі аргументи використовуючи операцію rest прямо в підпису функції.

Операція rest більш детально розглядається далі в курсі, тут же показано одне з її можливих застосувань. 

const fn = function(...args) {
  // В змінній args буде повноцінний масив
};

6. Патерн Guard Clause

Оператор if...else - це основний спосіб створення логічних дерев. Проте, складні вкладені розгалуження роблять код більш заплутаним і важким для розуміння.

Створимо функцію яка обробляє зняття грошей з особового рахунку в банку. Функція отримує суму для зняття і поточний баланс рахунку, після чого в залежності від умови, виконує той чи інший блок коду.

const withdraw = function(amount, balance) {
  if (amount === 0) {
    console.log('Для проведення операції введіть суму більше нуля.');
  } else if (amount > balance) {
    console.log('Недостатньо коштів на рахунку.');
  } else {
    console.log('Операція зняття коштів проведена.');
  }
};

withdraw(0, 300); // Для проведення операції введіть суму більше нуля.
withdraw(500, 300); // Недостатньо коштів на рахунку.
withdraw(100, 300); // Операція зняття коштів проведена.

Навіть в такому простому прикладі є група вкладених умовних операторів, серед яких не відразу можна виділити нормальний хід виконання коду через особливості синтаксису if...else.

Патерн guard clause - це спосіб використовувати можливість дострокового повернення з функції за допомогою оператора return, щоб зробити вкладені умовні вирази більш одновимірними.

Виділимо всі перевірки умов в окремі оператори if, після чого додаємо код, який йде в тілі else. В ідеальному випадку, повинен вийти плоский список умовних операторів, що йдуть один за іншим, а в кінці блок який виконується тільки в тому випадку якщо не виконується жоден if.

const withdraw = function(amount, balance) {
  /*
   * Перевіряється умова. Якщо воно виконується, відбувається
   * console.log і вихід з функції. Код йде після тіла if
   * не виконається.
   */
  if (amount === 0) {
    console.log('Для проведення операції введіть суму більше нуля.');
    return;
  }

  /*
   * Якщо умова першого if не виконалася, його тіло пропускається
   * і інтерпретатор доходить до цього if.
   * Перевіряється умова. Якщо воно виконується, відбувається
   * console.log і вихід з функції. Код йде після тіла if
   * не виконається.
   */
  if (amount > balance) {
    console.log('Недостатньо коштів на рахунку.');
    return;
  }

  /*
   * Якщо жоден з попередніх if не виконався,
   * інтерпретатор доходить до цього коду і виконує його.
   */
  console.log('Операція зняття коштів проведена.');
};

withdraw(0, 300); // Для проведення операції введіть суму більше нуля.
withdraw(500, 300); // Недостатньо коштів на рахунку.
withdraw(100, 300); // Операція зняття коштів проведена.

Використовуючи такий підхід отримуємо більш чистий, плоский і зрозумілий код, який легше рефакторити.

7. Оголошення функції

Інший спосіб створити функцію - використовувати ключове слово function на початку інструкції. Такий запис називається Оголошення функції (function declaration).

Інструкція визначає змінну add і привласнює їй задану функцію. Ця форма запису не вимагає обов'язкової крапки з комою після закриття фігурної дужки тіла функції.

function add(a, b, c) {
  return a + b + c;
}

Особливістю цього синтаксису є те, що функцію можна викликати до її оголошення в коді. Це може бути зручно, тому що не потрібно турбуватися про необхідність визначати всі функції вище того місця, де вони використовуються. Механізм підняття ідентифікаторів описаний тут.

add(1, 2, 3); // 6
print('text'); // text

function add(a, b, c) {
  return a + b + c;
}

function print(str) {
  console.log(str);
}

З іншого боку, при такому синтаксисі може бути складно відстежити зв'язок між місцем оголошення функції і місцем її виклику. Сучасні гайди по стилю коду, складені великими компаніями з багаторічним досвідом розробки, так само схиляється до використання функціональних виразів. Тому рекомендується використовувати функціональні вирази, замість оголошень функції.

// ❌ Погано
function fn() {}

// ✅ Добре
const fn = function() {};
