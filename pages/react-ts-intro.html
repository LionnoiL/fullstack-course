1. Навіщо TypeScript у React

React відмінно працює й на чистому JS (саме так ми його проходили). Але тільки-но компонентів стає багато, TypeScript починає економити години:

  • Props під контролем — забув передати проп або передав рядок замість числа? Помилка підсвітиться ще в редакторі, а не в рантаймі.
  • Автодоповнення — редактор знає, які пропси приймає компонент і які поля має об'єкт стану.
  • Безпечний рефакторинг — перейменував проп, і TS покаже всі місця, де його треба оновити.

Цей розділ спирається на два попередні: TypeScript (типи, інтерфейси, дженерики) і React (компоненти, стан, хуки). Тут ми з'єднуємо їх — тож якщо якийсь тип незрозумілий, зазирни в розділ TypeScript.

2. Створення проєкту

Найпростіше — стартер Vite з шаблоном react-ts (Vite ми теж проходили):

npm create vite@latest my-app -- --template react-ts
cd my-app && npm install && npm run dev

Компоненти тепер живуть у файлах .tsx — це JSX із підтримкою типів.

3. Перший типізований компонент

// Greeting.tsx
type GreetingProps = {
  name: string;
};

function Greeting({ name }: GreetingProps) {
  return <h1>Привіт, {name}!</h1>;
}

// <Greeting name="Ada" />   ✅
// <Greeting />              ❌ помилка: пропущено name

4. Виведення типів

Не треба анотувати геть усе — TypeScript багато виводить сам. Наприклад, тип значення, повернутого компонентом, або результат хука визначаються автоматично. Явно типізуй те, що приходить ззовні (пропси, дані з API), а решту лиши висновку типів.

5. .ts чи .tsx

  • .tsx — файли, де є JSX (компоненти);
  • .ts — звичайна логіка без JSX (утиліти, типи, хелпери).
