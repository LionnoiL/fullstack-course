1. Встановлення

Найпростіший старт — офіційний майстер, який поставить ESLint і створить конфіг, поставивши кілька питань:

npm init @eslint/config@latest

Або вручну:

npm install -D eslint

2. Плоский конфіг eslint.config.js

Починаючи з ESLint 9, стандарт — «плоский» конфіг у файлі eslint.config.js (замість старого .eslintrc). Це звичайний JS-модуль, що експортує масив об'єктів-конфігурацій.

// eslint.config.js
import js from '@eslint/js';

export default [
  js.configs.recommended,   // базовий набір рекомендованих правил
  {
    files: ['**/*.js'],
    languageOptions: {
      ecmaVersion: 'latest',
      sourceType: 'module',
    },
    rules: {
      'no-unused-vars': 'warn',
      'no-undef': 'error',
    },
  },
];

3. Запуск

npx eslint .            // перевірити весь проєкт
npx eslint src/app.js   // конкретний файл
npx eslint . --fix      // виправити те, що можна автоматично

Зручно додати скрипти в package.json:

"scripts": {
  "lint": "eslint .",
  "lint:fix": "eslint . --fix"
}

4. Глобальні змінні й оточення

Щоб ESLint знав про глобальні змінні браузера (window, document) чи Node (process), використай пакет globals:

import globals from 'globals';

export default [
  {
    languageOptions: {
      globals: { ...globals.browser, ...globals.node },
    },
  },
];

5. Ігнорування файлів

Файли, які не треба перевіряти, вказують окремим об'єктом з ignores:

export default [
  { ignores: ['dist/', 'node_modules/', '*.min.js'] },
  // ...решта конфігу
];

Порядок у масиві має значення: пізніші об'єкти перевизначають правила з попередніх. Тому базові рекомендовані конфіги ставлять першими, а свої налаштування — після них.
