1. Query vs Mutation

Процедури бувають двох видів, за аналогією з HTTP:

  • .query() — читання даних, без побічних ефектів (як GET). Результат можна кешувати;
  • .mutation() — зміна даних: створити, оновити, видалити (як POST/PUT/DELETE).
export const appRouter = router({
  list: publicProcedure.query(() => db.todos.findMany()),
  clear: publicProcedure.mutation(() => db.todos.deleteMany()),
});

2. Вхідні дані: .input() + Zod

Аргументи процедури описують Zod-схемою через .input(). tRPC перевіряє вхід цією схемою на рантаймі й одночасно виводить тип аргументу — усередині процедури input уже типізований, без ручних анотацій.

import { z } from 'zod';

export const appRouter = router({
  byId: publicProcedure
    .input(z.object({ id: z.number() }))
    .query(({ input }) => {
      // input: { id: number } — виведено зі схеми
      return db.todos.findById(input.id);
    }),
});

Якщо клієнт надішле дані, що не проходять схему, tRPC поверне помилку BAD_REQUEST ще до виконання твого коду. Тобто всередині процедури input уже гарантовано валідний — не треба перевіряти вручну.

3. Mutation зі входом

Мутації так само приймають .input(). Ось створення todo з валідацією:

add: publicProcedure
  .input(z.object({ title: z.string().min(1).max(200) }))
  .mutation(({ input }) => {
    return db.todos.create({ title: input.title, done: false });
  }),

toggle: publicProcedure
  .input(z.object({ id: z.number(), done: z.boolean() }))
  .mutation(({ input }) => db.todos.update(input.id, { done: input.done })),

4. Тип результату (і опційний .output())

Тип того, що процедура повертає, tRPC виводить автоматично зі return — окремо його описувати не треба. За бажання можна додати .output() зі схемою, щоб гарантувати форму відповіді (корисно, коли не хочеш випадково віддати зайві поля, як-от passwordHash):

const todoShape = z.object({ id: z.number(), title: z.string(), done: z.boolean() });

list: publicProcedure
  .output(z.array(todoShape)) // зайві поля буде відсічено/перевірено
  .query(() => db.todos.findMany()),

5. Асинхронні процедури

Процедура може бути async — tRPC чекає на проміс. Це звична робота з БД:

user: publicProcedure
  .input(z.object({ id: z.string() }))
  .query(async ({ input }) => {
    const user = await prisma.user.findUnique({ where: { id: input.id } });
    return user; // тип результату виведеться з Prisma
  }),

Тепер маємо процедури читання й запису з валідацією. Далі — як групувати їх у вкладені роутери й давати процедурам спільний контекст (БД, поточний користувач).
