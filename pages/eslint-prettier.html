1. У чому конфлікт

ESLint історично теж має правила форматування (відступи, лапки). Якщо їх лишити ввімкненими, ESLint і Prettier почнуть «перетягувати» код туди-сюди. Рішення — віддати все форматування Prettier, а в ESLint вимкнути стильові правила.

2. eslint-config-prettier

Пакет eslint-config-prettier вимикає всі правила ESLint, які конфліктують із Prettier. Його додають останнім у конфізі, щоб він перекрив стильові правила попередніх наборів. 

npm install -D eslint-config-prettier
// eslint.config.js
import js from '@eslint/js';
import prettier from 'eslint-config-prettier';

export default [
  js.configs.recommended,
  // ...твої правила...
  prettier,   // ← останнім: вимикає стильові правила ESLint
];

3. Розподіл обов'язків

  • ESLint — знаходить помилки й проблеми якості (eqeqeq, no-unused-vars, правила хуків тощо).
  • Prettier — відповідає за весь вигляд коду.

Раніше форматування вбудовували в ESLint через eslint-plugin-prettier. Зараз рекомендований підхід простіший: запускати Prettier окремо, а eslint-config-prettier лише гасить конфлікти. Менше шуму й швидша перевірка.

4. Порядок запуску

Типовий конвеєр: спершу відформатувати, потім перевірити якість.

"scripts": {
  "format": "prettier . --write",
  "lint": "eslint .",
  "check": "prettier . --check && eslint ."
}

5. Перевірка, що конфлікту немає

Швидкий тест: код, який Prettier вважає відформатованим, не має давати стильових скарг від ESLint. Якщо дає — eslint-config-prettier не підключено або стоїть не останнім.
