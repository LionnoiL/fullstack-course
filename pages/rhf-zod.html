1. Місток: zodResolver

Щоб RHF валідував форму за Zod-схемою, ставлять пакет-адаптер і передають схему в resolver.

npm install @hookform/resolvers zod
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const schema = z.object({
  email: z.string().email('Некоректний email'),
  password: z.string().min(8, 'Мінімум 8 символів'),
});

const { register, handleSubmit, formState: { errors } } = useForm({
  resolver: zodResolver(schema),
});

2. Повний приклад

function LoginForm() {
  const { register, handleSubmit, formState: { errors, isSubmitting } } =
    useForm({ resolver: zodResolver(schema) });

  const onSubmit = (data) => console.log(data); // вже валідні дані

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('email')} />
      {errors.email && <p className="error">{errors.email.message}</p>}

      <input type="password" {...register('password')} />
      {errors.password && <p className="error">{errors.password.message}</p>}

      <button disabled={isSubmitting}>Увійти</button>
    </form>
  );
}

Тепер правила живуть лише у схемі, а повідомлення про помилки автоматично потрапляють у errors за іменами полів.

Це і є цільова архітектура форм у 2026: RHF — механіка й продуктивність, Zod — правила й типи, zodResolver — місток між ними. Одна схема перевіряє форму на клієнті й може перевіряти запит на сервері.

3. Типізація форми зі схеми

З TypeScript тип значень форми беруть прямо зі схеми — жодного дублювання:

type FormData = z.infer<typeof schema>;

const { register } = useForm<FormData>({ resolver: zodResolver(schema) });
// register('emial') → помилка типу: такого поля немає

4. Початкові значення зі схемою

useForm<FormData>({
  resolver: zodResolver(schema),
  defaultValues: { email: '', password: '' },
});
