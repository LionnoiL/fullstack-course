Практика: tRPC

Створи монорепо (наприклад, Vite-клієнт + Node/Express-сервер або Next.js) і встанови @trpc/server, @trpc/client, @trpc/react-query, @tanstack/react-query, zod. Рухайся від першої процедури до захищеного CRUD.

Завдання 1. Перша процедура

Ініціалізуй tRPC (initTRPC.create()), зроби appRouter з однією query-процедурою greeting, що повертає { text: 'Hello tRPC' }, і експортуй тип AppRouter. Підключи адаптером до сервера.

Підказка

Винеси router і publicProcedure в окремий trpc.ts, щоб не було циклічних імпортів. Не забудь export type AppRouter = typeof appRouter;.

Рішення 
// trpc.ts
const t = initTRPC.create();
export const router = t.router;
export const publicProcedure = t.procedure;

// router.ts
export const appRouter = router({
  greeting: publicProcedure.query(() => ({ text: 'Hello tRPC' })),
});
export type AppRouter = typeof appRouter;

Завдання 2. Todo-роутер із входом (Zod)

Зроби окремий todoRouter з процедурами: list (query), add (mutation, вхід { title: string }, мін. 1 символ) і toggle (mutation, вхід { id: number, done: boolean }). Дані тримай у масиві в пам'яті. Вклади роутер у кореневий як todo.

Підказка

Вхід описуй через .input(z.object({ ... })). Усередині процедури input уже типізований — ручних анотацій не треба.

Рішення 
let todos = [{ id: 1, title: 'Вивчити tRPC', done: false }];

export const todoRouter = router({
  list: publicProcedure.query(() => todos),
  add: publicProcedure
    .input(z.object({ title: z.string().min(1) }))
    .mutation(({ input }) => {
      const todo = { id: Date.now(), title: input.title, done: false };
      todos.push(todo);
      return todo;
    }),
  toggle: publicProcedure
    .input(z.object({ id: z.number(), done: z.boolean() }))
    .mutation(({ input }) => {
      todos = todos.map((t) => (t.id === input.id ? { ...t, done: input.done } : t));
      return todos.find((t) => t.id === input.id);
    }),
});

Завдання 3. Клієнт із React Query

Створи trpc через createTRPCReact<AppRouter>(), налаштуй провайдери з httpBatchLink. Виведи список задач через useQuery, а форму додавання зроби на useMutation з інвалідацією списку через useUtils.

Рішення 
const { data } = trpc.todo.list.useQuery();
const utils = trpc.useUtils();
const add = trpc.todo.add.useMutation({
  onSuccess: () => utils.todo.list.invalidate(),
});

<button onClick={() => add.mutate({ title: 'Нова' })} disabled={add.isPending}>
  Додати
</button>

Завдання 4. Контекст і захищена процедура (виклик)

Додай createContext, що кладе user (з фейкового токена в заголовку) у контекст. Зроби protectedProcedure через middleware, що кидає TRPCError({ code: 'UNAUTHORIZED' }), якщо ctx.user порожній. Переведи add/toggle на protectedProcedure, а list лишай публічним.

Підказка

У middleware повертай next({ ctx: { user: ctx.user } }) — так тип user звузиться й перестане бути null у захищених процедурах. Тип контексту передай у initTRPC.context<Context>().

Візьми ту саму Zod-схему, що й у формах (RHF + Zod), і застосуй її і на вході процедури, і у формі на клієнті. Одне джерело правди для валідації й типів по всьому стеку — головна перевага TS-фулстеку.
