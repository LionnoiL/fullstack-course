1. Проблема ручного завантаження

Класичний спосіб отримати дані в React — useEffect + fetch + кілька useState. Швидко з'ясовується, що навколо кожного запиту доводиться писати той самий код: стан завантаження, обробка помилки, скасування, повторний запит, кешування.

// типовий бойлерплейт — і так для кожного запиту
const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(() => {
  setLoading(true);
  fetch('/api/todos')
    .then((r) => r.json())
    .then(setData)
    .catch(setError)
    .finally(() => setLoading(false));
}, []);

2. Серверний стан — особливий

Дані з сервера — це не звичайний стан застосунку. Вони живуть віддалено, можуть застаріти, оновлюватися іншими користувачами, кешуватися. TanStack Query (раніше React Query) — це бібліотека саме для серверного стану.

Розрізняй клієнтський стан (відкрите модальне вікно, введений текст — це useState/Zustand) і серверний стан (список товарів з API — це TanStack Query). Змішувати їх в одному сховищі — часта помилка.

3. Що дає з коробки

  • кешування й повторне використання даних між компонентами;
  • стани isPending / isError / data без ручних useState;
  • фонове оновлення застарілих даних (refetch);
  • дедуплікацію однакових запитів;
  • пагінацію, безкінечні списки, оптимістичні оновлення.

4. Той самий приклад із TanStack Query

const { data, isPending, error } = useQuery({
  queryKey: ['todos'],
  queryFn: () => fetch('/api/todos').then((r) => r.json()),
});

Три рядки замість десятка — і при цьому кеш, дедуплікація й фонове оновлення вже працюють. Далі розберемо це докладно.
