1. createAsyncThunk

Редюсери синхронні й чисті, тож запити роблять окремо — через thunk. createAsyncThunk сам генерує три стани дії: pending, fulfilled, rejected. 

import { createAsyncThunk } from '@reduxjs/toolkit';

export const fetchUsers = createAsyncThunk('users/fetch', async () => {
  const res = await fetch('/api/users');
  return res.json(); // потрапить у action.payload при fulfilled
});

2. Обробка в extraReducers

Стани тунка ловлять у extraReducers слайса:

const usersSlice = createSlice({
  name: 'users',
  initialState: { items: [], status: 'idle', error: null },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchUsers.pending,   (s) => { s.status = 'loading'; })
      .addCase(fetchUsers.fulfilled, (s, a) => {
        s.status = 'succeeded';
        s.items = a.payload;
      })
      .addCase(fetchUsers.rejected,  (s, a) => {
        s.status = 'failed';
        s.error = a.error.message;
      });
  },
});
// у компоненті
useEffect(() => { dispatch(fetchUsers()); }, [dispatch]);

3. RTK Query — коротко

Для роботи з API RTK має вбудований шар RTK Query — аналог TanStack Query всередині Redux (кеш, статуси, автогенеровані хуки). 

const api = createApi({
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  endpoints: (build) => ({
    getUsers: build.query({ query: () => 'users' }),
  }),
});
export const { useGetUsersQuery } = api;
// у компоненті: const { data, isLoading } = useGetUsersQuery();

4. Що обрати для серверних даних

Якщо застосунок уже на Redux — бери RTK Query. Якщо ні — TanStack Query простіший і не тягне за собою Redux. Головне: не тримай серверні дані в звичайних слайсах вручну — для цього є спеціальні інструменти.

5. Zustand vs Redux Toolkit — підсумок

  • Zustand — мінімум коду, швидкий старт, малі/середні застосунки.
  • Redux Toolkit — структура й патерни, потужні devtools, великі команди й застосунки; RTK Query для даних.
  • Для серверного стану в обох випадках згадай про TanStack Query / RTK Query.
