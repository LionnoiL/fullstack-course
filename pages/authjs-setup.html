1. Що таке Auth.js

Auth.js (раніше NextAuth.js) — популярна безкоштовна бібліотека автентифікації для веб-застосунків. Вона реалізує весь OAuth-потік з минулого уроку, керує сесіями й дає готові функції входу/виходу. Найкраще інтегрована з Next.js, але працює й з іншими фреймворками.

Приклади нижче — для Next.js (App Router) і Auth.js v5, бо це найтиповіша зв'язка. Ми спираємось на розділ Next.js: маршрути, middleware, серверні компоненти.

2. Встановлення

npm install next-auth@beta

Згенеруй секрет для підпису сесій і поклади змінні оточення:

// .env.local
AUTH_SECRET=згенерований_довгий_секрет   // npx auth secret
AUTH_GITHUB_ID=...
AUTH_GITHUB_SECRET=...

3. Головний конфіг

Уся конфігурація — в одному файлі. Тут перелічуємо провайдери й отримуємо хелпери: handlers (для роут-хендлера), auth (прочитати сесію), signIn/signOut. 

// auth.ts
import NextAuth from 'next-auth';
import GitHub from 'next-auth/providers/github';
import Google from 'next-auth/providers/google';

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [GitHub, Google],
});

4. Роут-хендлер

Auth.js обробляє всі свої запити (/api/auth/*) через один динамічний роут: 

// app/api/auth/[...nextauth]/route.ts
import { handlers } from '@/auth';
export const { GET, POST } = handlers;

Саме сюди провайдер повертає користувача (/api/auth/callback/github) — той самий Redirect URI, що ми реєстрували в консолі провайдера.

5. Види провайдерів

  • OAuth — Google, GitHub, Discord, Apple тощо (десятки з коробки);
  • Email (magic link) — вхід за посиланням з листа, без пароля;
  • Credentials — власна перевірка (email + пароль із твоєї БД), коли треба повний контроль. 
import Credentials from 'next-auth/providers/credentials';

providers: [
  Credentials({
    credentials: { email: {}, password: {} },
    authorize: async (creds) => {
      const user = await findUser(creds.email);
      if (user && (await verifyPassword(creds.password, user.hash))) return user;
      return null; // null → відмова у вході
    },
  }),
],

У Credentials перевірку пароля пишеш сам — тут якраз стають у пригоді bcrypt.compare з розділу «Бекенд». Auth.js бере на себе лише сесію та cookie.

6. Кнопки входу/виходу

// серверний компонент або server action
import { signIn, signOut } from '@/auth';

<form action={async () => { 'use server'; await signIn('github'); }}>
  <button>Увійти через GitHub</button>
</form>

<form action={async () => { 'use server'; await signOut(); }}>
  <button>Вийти</button>
</form>

Провайдери підключені — далі навчимося читати сесію й захищати сторінки.
