1. Що таке патерн проєктування

Патерн — це перевірене типове рішення поширеної задачі проєктування. Це не код, який можна скопіювати, а ідея, яку адаптуєш під ситуацію. Знання патернів дає спільну мову в команді («тут потрібен Observer») і вберігає від винаходження велосипеда.

Не тягни патерн заради патерну. Спочатку — проста робоча реалізація; патерн застосовуй, коли справді зʼявилась проблема, яку він розвʼязує. Зайва абстракція шкодить не менше за її брак.

2. Module — інкапсуляція

Ховає внутрішні деталі, назовні відкриває лише потрібне. У сучасному JS роль модуля виконують ES-модулі (файл = модуль), а всередині файлу — замикання. 

// counter.js — приватний стан + публічний API
let count = 0;                        // приватне (не експортується)
export function increment() { count++; }
export function get() { return count; }
// count ззовні недоступний — лише через increment/get

3. Singleton — єдиний екземпляр

Гарантує, що обʼєкт існує в одному примірнику (конфіг, зʼєднання з БД, кеш). В ES-модулях це майже безкоштовно: модуль виконується один раз, тож експортований екземпляр — уже сінглтон. 

// store.js
class Store { constructor() { this.data = {}; } }
export const store = new Store(); // усі імпорти отримають ТОЙ САМИЙ обʼєкт

4. Factory — створення без new

Функція-фабрика повертає готовий обʼєкт, ховаючи логіку його створення. Зручно, коли тип залежить від параметра. 

function createUser(role) {
  const base = { role, createdAt: Date.now() };
  if (role === 'admin') return { ...base, canDelete: true };
  return { ...base, canDelete: false };
}
const admin = createUser('admin');

5. Observer (Pub/Sub) — підписка на події

Обʼєкти підписуються на подію й отримують сповіщення, коли вона стається. На цьому патерні тримаються події DOM, стани (Redux/Zustand), реактивність. 

class EventBus {
  constructor() { this.listeners = {}; }
  on(event, fn) { (this.listeners[event] ??= []).push(fn); }
  emit(event, data) { (this.listeners[event] ?? []).forEach((fn) => fn(data)); }
}

const bus = new EventBus();
bus.on('login', (user) => console.log('увійшов', user.name));
bus.emit('login', { name: 'Аня' }); // → "увійшов Аня"

6. Strategy — взаємозамінні алгоритми

Виносить різні варіанти поведінки в окремі функції й обирає потрібну в рантаймі — замість купи if/else. 

const shipping = {
  standard: (w) => w * 5,
  express:  (w) => w * 5 + 50,
  pickup:   () => 0,
};
function cost(method, weight) {
  return (shipping[method] ?? shipping.standard)(weight);
}
cost('express', 2); // 60

Обʼєкт-словник функцій (як shipping вище) — ідіоматичний JS-спосіб Strategy: замість switch обираєш алгоритм за ключем. Легко додати новий варіант, не чіпаючи наявні.

7. Куди далі

Є ще десятки патернів (Facade, Decorator, Adapter, Command…). Але більшість щоденних задач у JS покривають саме ці пʼять — плюс уже знайомі тобі композиція функцій і модулі. Розпізнавай їх у чужому коді — і застосовуй свідомо, не заради краси.
