1. Збірка для продакшну

Команда npm run build збирає оптимізований застосунок у папку dist/. Під капотом працює Rollup: об'єднує модулі, мініфікує код, вирізає невикористане.

npm run build

// dist/index.html                 0.46 kB
// dist/assets/index-a1b2c3.css    4.12 kB │ gzip: 1.34 kB
// dist/assets/index-d4e5f6.js    142.9 kB │ gzip: 46.1 kB

2. Що робить збірка автоматично

  • Мініфікація JS і CSS — прибирає пробіли, скорочує імена.
  • Tree-shaking — вирізає код, який ніде не імпортується.
  • Code splitting — ділить бандл на частини, щоб браузер вантажив лише потрібне.
  • Хешування імен (index-a1b2c3.js) — для надійного кешування: змінився вміст → змінилось ім'я → браузер підвантажить нове.

3. Розбиття на частини (lazy loading)

Динамічний import() створює окремий чанк, який завантажиться лише за потреби — корисно для важких модулів чи маршрутів.

button.addEventListener('click', async () => {
  const { showChart } = await import('./chart.js'); // окремий чанк
  showChart();
});

4. Локальна перевірка збірки

Перед деплоєм переглянь саме зібрану версію (а не dev-сервер):

npm run build
npm run preview   // підніме статику з dist/ локально

5. Деплой

Результат у dist/ — це статичні файли. Їх можна залити на будь-який статичний хостинг: Netlify, Vercel, GitHub Pages, Cloudflare Pages чи звичайний Nginx.

Якщо застосунок деплоїться не в корінь домену, а в підпапку (напр. GitHub Pages: /repo/), задай базовий шлях: base: '/repo/' у vite.config.js — інакше шляхи до ассетів зламаються.
