1. Принципи REST

Ви вже вивчали REST із боку клієнта. Тепер збудуємо API на сервері. Нагадаємо принципи: ресурси адресуються через URL, а дії над ними виражаються HTTP-методами. 

GET    /api/users       // список
GET    /api/users/:id   // один
POST   /api/users       // створити
PUT    /api/users/:id   // оновити
DELETE /api/users/:id   // видалити

2. CRUD-контролери

Реалізуємо повний набір операцій (поки що з масивом у памʼяті замість БД).

const express = require('express');
const app = express();
app.use(express.json());

let users = [{ id: 1, name: 'Ada' }];

// список
app.get('/api/users', (req, res) => {
  res.json(users);
});

// один за id
app.get('/api/users/:id', (req, res) => {
  const user = users.find((u) => u.id === Number(req.params.id));
  if (!user) return res.status(404).json({ error: 'Не знайдено' });
  res.json(user);
});

// створити
app.post('/api/users', (req, res) => {
  const user = { id: Date.now(), name: req.body.name };
  users.push(user);
  res.status(201).json(user);
});

// видалити
app.delete('/api/users/:id', (req, res) => {
  users = users.filter((u) => u.id !== Number(req.params.id));
  res.status(204).end();
});

app.listen(3000);

3. Правильні коди статусів

  • 200 OK — успіх;
  • 201 Created — ресурс створено;
  • 204 No Content — успіх без тіла (видалення);
  • 400 Bad Request — некоректні дані;
  • 401 / 403 — не автентифіковано / немає прав;
  • 404 Not Found — ресурс відсутній;
  • 500 — помилка сервера.

Групуйте маршрути через express.Router() в окремі файли (routes/users.js) — так код лишається чистим, коли ендпоінтів стає багато.

4. Валідація вхідних даних

Ніколи не довіряйте даним від клієнта — перевіряйте їх на сервері (вручну або бібліотеками на кшталт zod, joi). 

app.post('/api/users', (req, res) => {
  const { name } = req.body;
  if (!name || name.trim().length < 2) {
    return res.status(400).json({ error: 'Імʼя обовʼязкове' });
  }
  // ...створення
});
