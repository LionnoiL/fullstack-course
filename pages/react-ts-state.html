1. Найчастіше тип виводиться сам

Якщо передати useState початкове значення, TypeScript сам визначить тип стану й сеттера. Явно нічого писати не треба.

const [count, setCount] = useState(0);        // number
const [name, setName]   = useState('Ada');    // string
const [open, setOpen]   = useState(false);    // boolean

setCount(count + 1); // ✅
setCount('багато');  // ❌ помилка типу

2. Явний тип через дженерик

Тип задають у кутових дужках, коли з початкового значення його не видно — наприклад, якщо стартуємо з null або порожнього масиву.

type User = { id: number; name: string };

// без явного типу тут вивелось би null, і .name дало б помилку
const [user, setUser] = useState<User | null>(null);

const [items, setItems] = useState<string[]>([]);

Порожній масив [] без дженерика виведеться як never[] — у нього не можна буде нічого покласти. Тому для масивів і об'єктів, що почнуться порожніми, завжди вказуй тип: useState<Todo[]>([]).

3. Робота зі станом, що може бути null

Коли стан має тип User | null, TS змусить перевірити наявність значення перед доступом до полів — це рятує від класичної помилки «cannot read property of null».

{user && <p>Вітаємо, {user.name}</p>}

// або з ранім виходом
if (!user) return <p>Завантаження…</p>;
return <p>{user.name}</p>;

4. Складний стан-об'єкт

type Form = { email: string; password: string };

const [form, setForm] = useState<Form>({ email: '', password: '' });

// оновлення поля — з розгортанням
setForm((prev) => ({ ...prev, email: 'a@b.com' }));

5. Ліниве початкове значення

// функція-ініціалізатор; тип виводиться з її результату
const [state, setState] = useState(() => expensiveInit());
