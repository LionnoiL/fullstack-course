1. Проблема рантайму

Класичні styled-components/Emotion — runtime CSS-in-JS: під час роботи в браузері бібліотека обчислює стилі, генерує класи й вставляє їх у <style>. Це зручно, але має ціну:

  • у бандл іде сама бібліотека (додатковий JS);
  • стилі рахуються при кожному рендері — навантаження на CPU;
  • погано дружить із React Server Components (нижче).

2. Чому це болить у Server Components

У Next.js App Router компоненти за замовчуванням серверні — без JS у браузері. Runtime CSS-in-JS потребує JS на клієнті, тож styled-components працюють лише в компонентах з 'use client'. Це змушує робити клієнтськими навіть суто презентаційні частини — втрачаєш переваги серверного рендеру.

Тому в екосистемі Next.js стався зсув: від runtime CSS-in-JS — до CSS Modules або zero-runtime рішень, які віддають звичайний CSS без клієнтського JS.

3. Zero-runtime CSS-in-JS

Zero-runtime — пишеш стилі в JS, але вся робота відбувається на етапі збірки: генерується статичний CSS-файл, а бібліотека в бандл не потрапляє. Це поєднує зручність CSS-in-JS зі швидкістю CSS Modules.

  • vanilla-extract — стилі в окремих *.css.ts-файлах із повною типізацією TypeScript; компілюється в статичний CSS;
  • Panda CSS — стилі-обʼєкти в JS + токени дизайн-системи; генерує CSS на збірці;
  • Linaria — синтаксис як у styled-components, але zero-runtime.
// vanilla-extract: button.css.ts — типізовано, компілюється в CSS
import { style } from '@vanilla-extract/css';

export const button = style({
  padding: '0.6rem 1.2rem',
  borderRadius: 6,
  background: '#2563eb',
  color: '#fff',
  ':hover': { background: '#1e40af' },
});
// у компоненті — як CSS Modules: імпортуєш згенерований клас
import { button } from './button.css';
<button className={button}>OK</button>

4. Токени й типобезпека

Сильна сторона zero-runtime — типізовані токени: кольори, відступи, шрифти описані в TS, і використати неіснуючий токен = помилка компіляції. Це те, що дизайн- системи (розділ «Дизайн-системи») люблять поєднувати з такими інструментами.

5. Що це означає на практиці

  • звичайний Vite/React-застосунок → CSS Modules або runtime CSS-in-JS — обидва ок;
  • Next.js App Router / серверний рендер / жорсткі вимоги до перформансу → CSS Modules або zero-runtime (vanilla-extract, Panda);
  • дизайн-система з токенами й строгими типами → zero-runtime.
