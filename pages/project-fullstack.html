Мілстоун 4: fullstack-нотатник (капстоун)

Етап: фінальний — після React/Next, бекенду й супровідних тем. Мета — повноцінний застосунок із фронтендом, сервером, базою даних і авторизацією. Це проєкт рівня портфоліо.

Функціонал

  • реєстрація й вхід користувача;
  • кожен користувач бачить лише свої нотатки;
  • CRUD нотаток: створити, переглянути, редагувати, видалити;
  • пошук/фільтр нотаток;
  • захищені маршрути (без входу — редірект).

Рекомендований стек

  • фронтенд: Next.js (App Router) + React;
  • бекенд: Route Handlers або окремий Express;
  • база даних: PostgreSQL + Prisma;
  • авторизація: JWT або сесії, паролі через bcrypt;
  • TypeScript наскрізно.

Вимоги

  • REST-ендпоінти з правильними статусами й валідацією вводу;
  • паролі зберігаються лише хешованими;
  • секрети — у змінних оточення (.env у .gitignore);
  • розділення відповідальності: маршрути / логіка / доступ до БД;
  • щонайменше кілька тестів ключової логіки;
  • задеплоєно (фронтенд + бекенд + БД).

Приклад моделі даних (Prisma)

model User {
  id       Int    @id @default(autoincrement())
  email    String @unique
  password String
  notes    Note[]
}

model Note {
  id        Int      @id @default(autoincrement())
  title     String
  body      String
  author    User     @relation(fields: [authorId], references: [id])
  authorId  Int
  createdAt DateTime @default(now())
}

Порядок роботи

  • спроєктуй модель даних і API;
  • підніми БД і Prisma, зроби міграцію;
  • реалізуй реєстрацію/вхід і видачу токена;
  • зроби захищені CRUD-ендпоінти нотаток;
  • збудуй UI: сторінки входу, списку, редагування;
  • додай обробку помилок і завантаження;
  • напиши тести й задеплой.

Не намагайся зробити все одразу. Спершу — «наскрізний зріз»: реєстрація → створення однієї нотатки → її показ. Коли працює повний ланцюг, нарощуй решту.

Розвиток проєкту

Ролі й спільний доступ до нотаток, теги й папки, markdown-редактор, вкладення файлів, реалтайм-оновлення через WebSocket.
