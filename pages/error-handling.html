1. Помилки під час виконання

Навіть синтаксично правильний код може «впасти» під час виконання: неіснуюча властивість, некоректний JSON, недоступна мережа. Такі ситуації називають винятками (exceptions). Якщо виняток не перехопити, він зупиняє виконання поточного коду. Механізм try...catch дозволяє опрацювати помилку і продовжити роботу.

2. try / catch / finally

try {
  const data = JSON.parse('{ поганий json }');
  console.log(data);
} catch (error) {
  // сюди потрапляємо, якщо в try сталася помилка
  console.error('Не вдалося розібрати:', error.message);
} finally {
  // виконається ЗАВЖДИ — і при помилці, і без неї
  console.log('Готово');
}

Блок catch отримує обʼєкт помилки. Найкорисніші його поля:

  • error.name — тип помилки (TypeError, SyntaxError...);
  • error.message — текстовий опис;
  • error.stack — стек викликів на момент помилки.

Не «ковтайте» помилки порожнім catch {}. Мовчазне ігнорування приховує баги. Мінімум — залогуйте помилку; краще — обробіть її свідомо або киньте далі.

3. Генерація власних помилок

Оператор throw кидає виняток самостійно. Кидати варто саме обʼєкт Error (а не рядок) — тоді буде коректний стек.

function divide(a, b) {
  if (b === 0) {
    throw new Error('Ділення на нуль заборонено');
  }
  return a / b;
}

try {
  divide(10, 0);
} catch (e) {
  console.log(e.message); // 'Ділення на нуль заборонено'
}

4. Вбудовані типи помилок

JavaScript має кілька стандартних класів помилок, що успадковуються від Error:

  • TypeError — значення не того типу (виклик не-функції тощо);
  • ReferenceError — звернення до неоголошеної змінної;
  • SyntaxError — некоректний синтаксис (напр., у JSON.parse);
  • RangeError — значення поза допустимим діапазоном.

5. Власні класи помилок

Для доменної логіки зручно створювати власні типи помилок — тоді в catch можна відрізняти їх через instanceof.

class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
  }
}

try {
  throw new ValidationError('Порожнє поле', 'email');
} catch (e) {
  if (e instanceof ValidationError) {
    console.log(`Помилка поля ${e.field}: ${e.message}`);
  } else {
    throw e; // не наша помилка — прокидаємо далі
  }
}

6. Помилки в асинхронному коді

try...catch не «бачить» помилок з колбеків setTimeout чи з проміса без await. Для промісів використовують .catch(), а в async-функціях — звичайний try...catch (детальніше в уроці про async / await).

async function load() {
  try {
    const res = await fetch('/api/data');
    return await res.json();
  } catch (e) {
    console.error('Запит не вдався:', e.message);
  }
}
