1. Навіщо це фулстек-розробнику

У 2026 «AI-фіча» — це вже не окремий продукт, а звичайний елемент застосунку: чат підтримки, пошук за змістом, підсумки, автозаповнення, класифікація, генерація чернеток. Для тебе це ще один зовнішній API, який викликаєш з бекенду й показуєш результат на фронті. Уся складність — у деталях: стрімінг, вартість, контекст, безпека ключів.

2. Як влаштований чат-API

Ти надсилаєш список повідомлень з ролями, а модель повертає наступне повідомлення. Ролі:

  • system — інструкція, що задає поведінку («ти — асистент підтримки, відповідай українською»);
  • user — репліки користувача;
  • assistant — попередні відповіді моделі.

API без стану: сервер не памʼятає діалог. Щоб модель «памʼятала» контекст, ти щоразу надсилаєш усю історію повідомлень. Це важливо для розуміння вартості (нижче).

3. Токени й вартість

Моделі оперують токенами — шматками тексту (приблизно ¾ слова). Оплата йде за токени входу (твій промпт + історія) і виходу (відповідь). Тому:

  • довга історія діалогу коштує дорожче з кожним ходом;
  • max_tokens обмежує довжину відповіді;
  • у моделей є контекстне вікно — максимум токенів на запит (напр. 200K–1M).

4. Провайдери й моделі

Основні LLM-провайдери — Anthropic (моделі Claude) та OpenAI (GPT). API схожі за формою (ролі, повідомлення, стрімінг, виклик інструментів), тож знання переносяться. У прикладах цього розділу використаємо Anthropic SDK; актуальні моделі Claude на момент курсу — claude-opus-4-8 (найпотужніша), claude-sonnet-4-6 (баланс) і claude-haiku-4-5 (швидка й дешева).

Обирай модель під задачу: проста класифікація — швидка/дешева модель; складні міркування чи агентні задачі — найпотужніша. Керувати «творчістю» відповіді в сучасних моделях зазвичай простіше формулюванням промпту, ніж параметрами.

5. Безпека: ключ — тільки на сервері

API-ключ провайдера дає доступ до платного акаунта. Він має жити лише на бекенді, у змінних оточення. Ніколи не клади його у фронтенд-код чи публічні змінні (VITE_…/NEXT_PUBLIC_…) — вони потрапляють у бандл, і ключ украдуть.

// .env на сервері (не комітити!)
ANTHROPIC_API_KEY=sk-ant-...

// фронтенд шле запит на ТВІЙ бекенд, а той уже — до LLM
fetch('/api/chat', { method: 'POST', body: JSON.stringify({ message }) });

Браузер ніколи не звертається до LLM-провайдера напряму зі своїм ключем. Завжди через власний бекенд-проксі — там і ключ, і контроль (ліміти, логи, модерація).
