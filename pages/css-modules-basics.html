1. Що таке CSS Modules

CSS Modules — це звичайний CSS у файлі з розширенням .module.css. Під час збірки кожен клас перетворюється на унікальне імʼя (напр. Button_primary__a1b2c), тож стилі одного компонента не зачіпають інші. Жодної нової мови — той самий CSS, лише локальний.

CSS Modules підтримуються «з коробки» у Vite та Next.js — окремо нічого встановлювати не треба. Достатньо назвати файл *.module.css.

2. Файл стилів

/* Button.module.css — звичайний CSS */
.button {
  padding: 0.6rem 1.2rem;
  border: none;
  border-radius: 6px;
  cursor: pointer;
}
.primary {
  background: #2563eb;
  color: #fff;
}

3. Імпорт і використання

Модуль імпортують як обʼєкт: ключі — твої класи, значення — згенеровані унікальні імена. У JSX підставляєш styles.button, а не рядок "button". 

import styles from './Button.module.css';

export function Button({ children }) {
  return (
    <button className={`${styles.button} ${styles.primary}`}>
      {children}
    </button>
  );
}
// у розмітці клас буде типу class="Button_button__a1b2 Button_primary__c3d4"

Звертайся до класу лише через обʼєкт styles.button. Написати className="button" не спрацює — реального класу button у зібраному CSS немає, він перейменований.

4. Імена з дефісом

Клас .primary-btn у JS не можна написати як styles.primary-btn (дефіс = мінус). Або звертайся через дужки, або називай класи в camelCase: 

styles['primary-btn']   // так — для класів із дефісом
styles.primaryBtn       // краще: називай класи camelCase у .module.css

5. Що це дає

  • ізоляція — класи компонента не конфліктують із іншими;
  • звичайний CSS — усі знання (media queries, псевдокласи, grid) працюють;
  • zero-runtime — уся робота на етапі збірки, у браузер іде звичайний CSS без зайвого JS;
  • мертвий код видно — невикористаний ключ styles.x легко знайти.

Далі — потужніші можливості: composes, глобальні винятки, динамічні класи й типізація в TypeScript.
