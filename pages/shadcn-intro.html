1. Що таке shadcn/ui

shadcn/ui — це колекція гарних, доступних компонентів на базі Radix і Tailwind CSS. Головна відмінність: це не npm-бібліотека, яку ти встановлюєш і імпортуєш. Натомість CLI копіює код компонента у твій проєкт — і далі він твій.

Гасло shadcn/ui — «this is not a component library, it's how you build your component library». Ти отримуєш стартовий код, який вільно редагуєш, а не чорну скриньку в node_modules, обмежену чужим API.

2. Чому копіювати код — це добре

  • Повний контроль: компонент лежить у твоєму components/ui — міняй розмітку й стилі як завгодно.
  • Немає версійного пекла: оновлення бібліотеки не зламає твій UI, бо код уже твій.
  • Прозорість: видно, як усе влаштовано, — гарний спосіб вчитися.
  • Доступність у подарунок: усередині Radix, тож a11y на місці.

3. Ціна підходу

  • код компонентів — тепер твоя відповідальність (сам стежиш за оновленнями);
  • потрібні React + Tailwind у проєкті;
  • більше файлів у репозиторії, ніж один пакет-залежність.

4. З чого складається компонент

Типовий компонент shadcn/ui — це React-обгортка над Radix-примітивом зі стилями Tailwind і зручним API варіантів (через class-variance-authority). 

// приклад згенерованого button.tsx (спрощено)
const buttonVariants = cva('inline-flex items-center rounded-md', {
  variants: {
    variant: { default: 'bg-primary text-white', ghost: 'hover:bg-accent' },
    size: { sm: 'h-8 px-3', md: 'h-10 px-4' },
  },
  defaultVariants: { variant: 'default', size: 'md' },
});

5. Коли обирати

Ідеально, коли потрібен унікальний, повністю кастомний UI на React + Tailwind, і ти хочеш володіти кодом компонентів. Для швидкого прототипу з дефолтним виглядом готова бібліотека може бути простішою.
