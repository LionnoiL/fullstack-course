1. Що таке деплой

Деплой (deployment) — це публікація застосунку, щоб він став доступним користувачам в інтернеті. Фронтенд і бекенд деплоять по-різному.

2. Деплой фронтенду

Статичний сайт чи SPA спершу збирають, а тоді викладають на хостинг статики (Vercel, Netlify, GitHub Pages).

npm run build   # створює папку dist/ з оптимізованими файлами

На Vercel/Netlify достатньо підключити Git-репозиторій — вони самі збирають і публікують при кожному пуші.

3. Деплой бекенду

Сервер Node.js потребує середовища виконання. Платформи: Render, Railway, Fly.io, VPS. Обовʼязково задають змінні оточення (БД, секрети) на самій платформі.

4. Docker (контейнеризація)

Docker пакує застосунок разом із залежностями в контейнер, який однаково працює будь-де — «на моїй машині працює» більше не проблема.

# Dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 3000
CMD ["node", "src/index.js"]

5. CI/CD

CI/CD — автоматичний конвеєр: при пуші в Git запускаються тести й лінтери (CI), а якщо все зелене — застосунок автоматично публікується (CD). Приклад — GitHub Actions.

# .github/workflows/ci.yml
name: CI
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npm test

Для навчальних проєктів найпростіший шлях: фронтенд — на Vercel, бекенд — на Render, база — керований PostgreSQL. Усе має безкоштовні тарифи й підключення через Git.

6. Чекліст перед деплоєм

  • секрети у змінних оточення, а не в коді;
  • увімкнено production-режим і HTTPS;
  • тести проходять;
  • налаштовано CORS під реальний домен.

7. Додаткові матеріали

  • GitHub Actions — документація
  • Docker — початок роботи
