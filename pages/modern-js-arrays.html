1. Проблема мутуючих методів

Класичні sort(), reverse(), splice() змінюють сам масив (мутують). У сучасному коді (особливо в React, де стан має бути незмінним) це джерело багів: відсортував — і випадково зіпсував оригінал. 

const nums = [3, 1, 2];
const sorted = nums.sort();   // мутує nums!
console.log(nums);            // [1, 2, 3] — оригінал змінено 😱

2. Незмінні аналоги (ES2023)

З’явилися методи, що повертають новий масив, лишаючи оригінал недоторканим: 

const nums = [3, 1, 2];

const sorted   = nums.toSorted((a, b) => a - b); // [1, 2, 3]
const reversed = nums.toReversed();              // [2, 1, 3]
const spliced  = nums.toSpliced(1, 1);           // [3, 2] (видалити 1 з індексу 1)
const replaced = nums.with(0, 99);               // [99, 1, 2] (замінити індекс 0)

console.log(nums); // [3, 1, 2] — оригінал НЕ змінено ✅

Правило: у React та скрізь, де важлива незмінність, віддавай перевагу toSorted/toReversed/toSpliced/with. Раніше писали [...arr].sort() — тепер це вбудовано.

3. at() — доступ з кінця

at() дозволяє індекс від кінця через відʼємне число — зручніше за arr[arr.length - 1]: 

const arr = ['a', 'b', 'c'];
arr.at(0);   // 'a'
arr.at(-1);  // 'c'  — останній
arr.at(-2);  // 'b'
'hello'.at(-1); // 'o' — працює і для рядків

4. findLast і findLastIndex

Шукають з кінця масиву — коли потрібен останній елемент за умовою:

const nums = [1, 2, 3, 4, 5];
nums.findLast((n) => n % 2 === 0);      // 4 (останнє парне)
nums.findLastIndex((n) => n % 2 === 0); // 3 (його індекс)

5. Підтримка

Ці методи — стандарт у сучасних браузерах і Node (18+). Якщо потрібна підтримка дуже старих середовищ, білдер (Vite) із поліфілами вирівняє це за тебе. Перевірити сумісність можна на Can I use.
