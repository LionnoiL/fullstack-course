1. Навіщо база даних

Дані застосунку мають зберігатися постійно — між перезапусками сервера й для багатьох користувачів. Для цього використовують базу даних (БД). Є два великі типи: реляційні (SQL) і документні (NoSQL).

2. Реляційні БД (SQL)

Дані зберігаються в таблицях зі звʼязками між ними. Приклади: PostgreSQL, MySQL, SQLite. Мова запитів — SQL. 

CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE
);

INSERT INTO users (name, email) VALUES ('Ada', 'ada@site.com');

SELECT * FROM users WHERE id = 1;

UPDATE users SET name = 'Ada L.' WHERE id = 1;

DELETE FROM users WHERE id = 1;

3. Звʼязки між таблицями

Реляційні БД сильні саме звʼязками: користувач має багато замовлень, замовлення належить користувачу (через foreign key). 

CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  total NUMERIC
);

-- обʼєднання даних
SELECT users.name, orders.total
FROM orders
JOIN users ON users.id = orders.user_id;

4. Документні БД (NoSQL)

MongoDB зберігає дані як гнучкі JSON-подібні документи без жорсткої схеми. Зручно, коли структура даних змінюється або вкладена. 

// документ у колекції users
{
  _id: ObjectId("..."),
  name: "Ada",
  email: "ada@site.com",
  roles: ["admin", "user"]
}

db.users.find({ name: "Ada" });
db.users.insertOne({ name: "Grace" });

5. SQL чи NoSQL?

  • SQL — коли дані структуровані й важливі звʼязки та цілісність (фінанси, облік);
  • NoSQL — коли схема гнучка, потрібна швидкість і масштабування (логи, каталоги).

Для більшості вебзастосунків PostgreSQL — надійний вибір за замовчуванням. Писати «сирий» SQL із коду незручно й небезпечно (SQL-інʼєкції), тому далі використовують ORM — про це наступний урок.
