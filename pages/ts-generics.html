1. Навіщо дженерики

Дженерики (generics) — це «типи-параметри». Вони дозволяють написати універсальний код, який працює з різними типами, зберігаючи інформацію про конкретний тип, а не втрачаючи її через any.

// Погано: втрачаємо тип
function firstAny(arr: any[]): any {
  return arr[0];
}

// Добре: T «запамʼятовує» тип масиву
function first<T>(arr: T[]): T {
  return arr[0];
}

const n = first([1, 2, 3]);      // n: number
const s = first(['a', 'b']);     // s: string

2. Кілька типів-параметрів

function pair<K, V>(key: K, value: V): [K, V] {
  return [key, value];
}

const p = pair('age', 30); // [string, number]

3. Обмеження (constraints)

Через extends можна вимагати, щоб тип-параметр мав певні властивості.

function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}

longest('aaa', 'bb');       // ✅ рядки мають length
longest([1, 2], [1]);       // ✅ масиви теж
longest(10, 20);            // ❌ у числа немає length

4. Дженерик-інтерфейси та класи

interface ApiResponse<T> {
  data: T;
  status: number;
}

const userResp: ApiResponse<{ name: string }> = {
  data: { name: 'Ada' },
  status: 200,
};

class Box<T> {
  constructor(public value: T) {}
  get(): T {
    return this.value;
  }
}

const box = new Box<number>(42);

5. Типи за замовчуванням

interface Container<T = string> {
  items: T[];
}

const c: Container = { items: ['a', 'b'] }; // T = string за замовчуванням

Дженерики всюди в стандартній бібліотеці: Array<T>, Promise<T>, Map<K, V>. Розуміння дженериків — ключ до читання типів у реальних проєктах.
