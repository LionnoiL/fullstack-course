1. Основне правило

Головний принцип безпеки: ніколи не довіряй даним від клієнта. Будь-який ввід може бути шкідливим. Розглянемо найпоширеніші вразливості й захист від них.

2. XSS (міжсайтовий скриптинг)

Атака, коли зловмисник вставляє свій JS-код через поля вводу, і той виконується у браузерах інших користувачів.

// ❌ небезпечно: вставляємо ввід користувача як HTML
element.innerHTML = userInput; // може містити <script>

// ✅ безпечно: як текст
element.textContent = userInput;

Захист: екранування виводу, textContent замість innerHTML, а на сервері — заголовок Content-Security-Policy.

3. SQL-інʼєкції

Коли ввід підставляють прямо в SQL-запит, зловмисник може змінити його логіку.

// ❌ вразливо
db.query(`SELECT * FROM users WHERE name = '${userInput}'`);

// ✅ параметризований запит (або ORM)
db.query('SELECT * FROM users WHERE name = $1', [userInput]);

ORM (як Prisma з попереднього розділу) захищає від SQL-інʼєкцій за замовчуванням, бо завжди параметризує запити.

4. CSRF

Підробка запиту: сторонній сайт змушує браузер користувача виконати дію на сайті, де той авторизований. Захист: CSRF-токени, SameSite-cookie.

5. Паролі, секрети, HTTPS

  • паролі — лише хешовані (bcrypt), ніколи у відкритому вигляді;
  • секрети — у змінних оточення, не в коді й не в git;
  • завжди HTTPS — шифрує трафік між клієнтом і сервером;
  • оновлюйте залежності (npm audit) — уразливості часто в пакетах.

6. Додатковий захист

  • валідація й обмеження вводу на сервері;
  • rate limiting проти перебору й DoS;
  • helmet для безпечних HTTP-заголовків;
  • коректне налаштування CORS.
