Практика: Auth-провайдери

Візьми Next.js-проєкт (App Router) і додай автентифікацію через Auth.js, а тоді спробуй альтернативу — Supabase. Мета — відчути весь потік: провайдер → сесія → захист роутів → ролі.

Завдання 1. Вхід через GitHub (Auth.js)

Встанови next-auth@beta, налаштуй auth.ts з GitHub-провайдером і роут-хендлер app/api/auth/[...nextauth]/route.ts. Додай кнопки «Увійти»/«Вийти». Зареєструй OAuth-застосунок у GitHub і пропиши Redirect URI.

Підказка

Redirect URI у налаштуваннях GitHub — http://localhost:3000/api/auth/callback/github. Секрет згенеруй через npx auth secret.

Рішення 
// auth.ts
import NextAuth from 'next-auth';
import GitHub from 'next-auth/providers/github';
export const { handlers, auth, signIn, signOut } = NextAuth({ providers: [GitHub] });

// app/api/auth/[...nextauth]/route.ts
export const { GET, POST } = handlers;

Завдання 2. Показати сесію

На головній сторінці (серверний компонент) прочитай сесію через auth(). Якщо користувач увійшов — покажи його імʼя та email, інакше — кнопку входу.

Рішення 
const session = await auth();
return session
  ? <p>Привіт, {session.user?.name} ({session.user?.email})</p>
  : <LoginButton />;

Завдання 3. Захистити /dashboard

Додай middleware.ts, що пускає на /dashboard лише залогінених, а решту редіректить на сторінку входу. Використай matcher.

Підказка

Найпростіше — реекспорт: export { auth as middleware } from '@/auth'; плюс config.matcher. Тонший контроль — через колбек authorized.

Рішення 
// middleware.ts
export { auth as middleware } from '@/auth';
export const config = { matcher: ['/dashboard/:path*'] };

Завдання 4. Ролі через колбеки

У колбеках jwt і session прокинь поле role в сесію. На сторінці /admin (server action чи компонент) дозволь дію лише для role === 'admin', інакше кидай помилку доступу.

Рішення 
callbacks: {
  async jwt({ token, user }) { if (user) token.role = user.role; return token; },
  async session({ session, token }) {
    if (session.user) session.user.role = token.role;
    return session;
  },
},
// на сторінці:
if (session?.user?.role !== 'admin') throw new Error('403');

Завдання 5. Той самий вхід через Supabase (виклик)

В окремій гілці/проєкті під'єднай @supabase/supabase-js: реалізуй реєстрацію й вхід (email+пароль) та signInWithOAuth('github'). Додай до однієї таблиці RLS-політику «користувач бачить лише свої рядки» (auth.uid() = user_id) і переконайся, що чужі дані не повертаються.

Порівняй два підходи: з Auth.js користувачі у твоїй БД і повний контроль; із Supabase auth і дані живуть на платформі, а RLS переносить авторизацію в саму базу. Занотуй, що зручніше саме для твого fullstack-проєкту.
