1. Встановлення

На сервері потрібні @trpc/server і zod, на клієнті — @trpc/client (а для React ще @trpc/react-query з @tanstack/react-query). У монорепо ставимо все разом: 

npm install @trpc/server @trpc/client zod
# для React-клієнта (наступні уроки):
npm install @trpc/react-query @tanstack/react-query

tRPC потребує TypeScript у strict-режимі ("strict": true у tsconfig.json). Саме на суворих типах тримається виведення назв процедур і їхніх аргументів.

2. Ініціалізація: initTRPC

Усе починається з одного разу створеного екземпляра tRPC. З нього ми дістаємо будівельні блоки: router (щоб збирати роутери) і procedure (базова процедура, від якої походять усі інші). Виносимо це в окремий файл, щоб уникнути циклічних імпортів. 

// server/trpc.ts — ядро, створюємо РІВНО один раз
import { initTRPC } from '@trpc/server';

const t = initTRPC.create();

// експортуємо будівельні блоки, а не сам `t`
export const router = t.router;
export const publicProcedure = t.procedure;

3. Перша процедура й роутер

Процедура — це один ендпоінт (аналог маршруту в REST). Роутер — набір процедур. Найпростіша процедура-query просто щось повертає: 

// server/router.ts
import { router, publicProcedure } from './trpc';

export const appRouter = router({
  hello: publicProcedure.query(() => {
    return { message: 'Привіт із tRPC!' };
  }),
});

// ГОЛОВНЕ: експортуємо ТИП роутера — його імпортує клієнт
export type AppRouter = typeof appRouter;

export type AppRouter = typeof appRouter; — це той самий тип зі схеми в попередньому уроці. Клієнт імпортує його через import type, тож жоден рядок серверного коду не потрапляє в бандл фронтенду.

4. Підключення до сервера (адаптер)

Роутер сам не слухає порт — його «вмикають» через адаптер під конкретний сервер. Для окремого Node/Express це @trpc/server/adapters/express: 

// server/index.ts
import express from 'express';
import { createExpressMiddleware } from '@trpc/server/adapters/express';
import { appRouter } from './router';

const app = express();
app.use('/trpc', createExpressMiddleware({ router: appRouter }));
app.listen(3000);

У Next.js замість цього використовують Route Handler (app/api/trpc/[trpc]/route.ts) з fetchRequestHandler — принцип той самий, змінюється лише адаптер.

5. Підсумок структури

  • server/trpc.ts — initTRPC.create(), експорт router та publicProcedure;
  • server/router.ts — appRouter і export type AppRouter;
  • server/index.ts — адаптер, що вмикає роутер у HTTP-сервер.

У наступному уроці наповнимо роутер процедурами: query для читання, mutation для змін, і додамо валідацію входів через Zod.
